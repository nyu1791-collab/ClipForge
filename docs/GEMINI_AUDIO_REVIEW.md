# 現在の通常経路：音声理解 → 採用区間だけ文字起こし

2026-10-26の追加指示により、全文の3.5文字起こしと全文GPU ASRを通常経路から外す。以下が旧ASR先行経路に優先する。

1. runnerで音声だけを取得するか、保存済み元音声を再利用する。ASRファイルは要求しない。
2. 3.8 Flash / MEDIUM が音声から完結する話題の区間・要点・重要度を返す。全文テキストは生成しない。入力上限のため90分ごとの音声窓に分け、窓の端で話題が途切れる候補は除く。足りなければ自動再送せず停止する。
3. 重複しない5本（各300〜900秒）を採用。3.5 Flash / MINIMAL は話題の資料から固有名詞の表記を出典付きで調べる。全文文字起こしは担当しない。
4. 採用音声を話題ごとに仮切り出し、3.8 Flash / MEDIUMを1本につき1回呼ぶ。要約・言い換え・7〜8割への圧縮・15文字単位の細分化は禁止。無意味なフィラーと噛み直し前の断片だけを省く。その他の発言、意味のある相槌・驚き・否定・数字・条件・結論は残す。
5. 話者は短い参照音声を次の採用音声の冒頭に連結して照合する。参照部分は文字起こし対象外。確信できなければ通常色。通常2行・必要時3行で横幅を使って表示する。
6. Colab GPU/NVENCが選択区間だけ360pで取得し、選択区間の字幕を描画する。GPU ASRは実行しない。保存されたレビューと描画入力が一致しなければ停止する。

実装は `python -m clipforge.audio_understanding acquire|plan|render`。`plan --audio ORIGINAL_AUDIO --url SOURCE_URL --output NEW_DIRECTORY --config config.landscape-long.example.json` はASRなしで動作する。保存済み応答は別出力先と `--resume-from ORIGINAL_OUTPUT` で再生できる（同じ音声ハッシュ・URL・設定が必要）。

呼び出し回数は音声窓の数＋3.5調査1回＋採用本数。通常のテキスト候補計画や旧音声編集呼び出しを重ねない。指定Vertex OIDCだけを使用し、再送・別モデルへの切替はしない。音声入力とモデル応答は非公開Releaseへ保存する。

字幕時刻はGeminiが採用音声を聞いて推定した発話区間。`timestamp_source=gemini_estimated`、`timestamp_alignment=not_forced_aligned` を記録し、単語レベルの正確さや強制アライメント実施を保証しない。非数値・範囲外・逆転・重複・未完了の字幕応答は描画しない。強制アライメントは未実装。全文ASRへ自動で戻さない。

原音・既存ASR・応答・納品済み動画を削除しない。以下は過去の保存済み結果の再現用に残す旧工程であり、新規制作の入口に使わない。

# 保存済みASRから作る字幕の編集工程

2026-10-26 の依頼を反映。既存の完成動画は再生成せず、次の制作に適用する。元音声・Parakeet ASR・応答原本は残す。

## モデルの役割

`python -m clipforge.gemini_audio_editor --analysis ANALYSIS_DIRECTORY --output NEW_OUTPUT_DIRECTORY --config config.landscape-long.example.json --asr-first`

1. 保存済みParakeetと単語時刻を復元する。取得・ASRを繰り返さない。
2. Gemini 3.8 Flash / MEDIUM を1回呼び、5本の完結した区間（各300〜900秒）を選ぶ。
3. Gemini 3.5 Flash / MINIMAL を1回呼び、採用区間の公開活動名・人名・企画名・地名の表記をGoogle検索で調べる。最大20語、本人の公開プロフィール・公式告知を優先。非公開情報や実名の特定はしない。
4. 採用音声を1つに連結し、3.8 Flash / MEDIUM に1回渡す。出典付き表記候補を参照し、字幕の修正、意味を保つケバ取り、匿名の話者IDを同じ呼び出しで返させる。
5. 元の単語時刻に対応する差分だけを字幕へ適用し、話者注釈と一緒に `final-selection.json` へ保存する。描画はそのJSONと同じコードの40桁SHAを使い、360pのColab GPU/NVENCで行う。

ASR先行の音声編集経路は計3リクエスト。従来の2回に、利用者が指定した3.5の表記調査を1回追加する。自動再送・別モデルへの切替はしない。Google検索のモデル対応や実課金額は実行前のコード確認だけでは保証できない。未対応なら失敗を記録して停止する。

通常のテキストだけの候補計画（`vertex_selection.py`、3.8の指示→3.5の軽作業2件→3.8の選定、計4回）には音声入力がない。そこで声質や話者IDを推定しない。話者色と音声に基づくケバ取りを使う制作では、この音声編集経路を選ぶ。音声編集にさらに通常の候補計画を重ねない。

認証は指定VertexプロジェクトのGitHub OIDC短期アクセストークンを `CLIPFORGE_VERTEX_ACCESS_TOKEN` へ渡す既存の方式。資格情報はモデルへ渡さない。入力・応答・使用量・検索情報は非公開Releaseだけに保存する。

## 表記の扱い

3.5の提案は `surface / preferred / source_urls / evidence / confidence` を持つ。ASRにある語で、確信度0.9以上、出典がAPIの `groundingChunks` と `groundingSupports` の両方に対応する候補だけを3.8へ渡す。出典の付かない回答・架空URL・曖昧な候補は採用しない。検索の引用だけで正解と断定せず、3.8が原音と会話の文脈を照合する。例えば「南／ミナミ」は、対象の公開活動名を特定できなければ元表記を維持し、未確認と記録する。一律の文字列置換はしない。

## 表示字幕のケバ取り

- 無意味な「えー」「あのー」、言い淀み、単純な吃り、言い直し前の未完の断片を省く。
- 気付きや驚きの「ああ」、返答の「うん」、ためらい自体に意味がある表現、笑いや話の要点は残す。
- 否定・数字・条件・固有名詞・主張・結論・オチは落とさず、要約や発言の創作はしない。
- 清書結果を単語境界の差分に変換する。変更していない単語の時刻を保持する。不確かな行・対応できない差分は修正せず記録する。表示字幕だけを変更し、音声を切り詰めない。

## 話者と横長レイアウト

`src/clipforge/speaker_captions.py` が匿名IDと色を管理する。話者は出現順の `speaker_1`〜`speaker_6`。5本を通して同じ声に同じID・色を使う。笑い・叫び・一時的な声の高さだけで別人にしない。ASR文から人物・属性を推測しない。0.8未満、不明、同時発話、一つのASR行に複数の声がある場合は通常色。未知ID・重複IDも通常色に戻す。

描画へ渡す `speaker_turns` はクリップ先頭を0秒とする `start / end / speaker_id / confidence`。時刻はモデルが生成せず保存済みASRから作る。話者が変わるところで字幕を分け、話者が曖昧な区間をまたいで色付けしない。カラオケでも話者の色相を維持し、SRTには装飾を入れない。元動画の切り出しに伴うremuxオフセットを、この出力相対時刻へ二重適用しない。話者注釈も描画キャッシュの識別子へ含める。

横長の既定は1行30全角文字を目安とし、画面と余白に収まる幅が上限。通常2行、文のまとまりを保つため必要な場合だけ3行。短文を2.5秒程度のまとまりにし、発話の区切りは最長8秒を目安にする。長い無音と話者交代では区切る。読み取り用の延長は次の字幕・クリップ終端まで。別の人が話し始めた後に前の字幕を残したり、早く切り替えて次の発言を先出ししたりしない。縦画面は従来の2行を維持する。

Pillowとlibassのフォントサイズの定義の差を補正して幅を測る。文字サイズを縮小して横へ詰めるのではなく、描画時の実際の文字幅で改行する。

## 記録と再開

`audio-editor-receipt.json` は各リクエストのモデル、思考レベル、使用量、HTTP状態、開始終了、実時間を記録する。`terminology-glossary.json` に採用候補と根拠の検査結果、`audio-review-summary.json` に字幕修正と話者注釈の適用結果を残す。選定・検索・音声準備の時間を混ぜず、並列時間を足して実時間としない。請求額はusageだけでは断定しない。

`--resume-from SAVED_RESPONSE_DIRECTORY --asr-first` は保存済みの2段階または3段階応答を再生する。モデル呼び出し・音声変換は行わない。旧応答にない検索結果や話者IDを後から捏造しない。音声を読めなかった応答や未完了応答では描画しない。

`--asr-first` を省いた旧全文再文字起こし経路は互換性のため残るが、今回の工程では使わない。完成動画の全量監査、音量再測定、自動再描画は追加しない。

## 2026-10-26 部分再開と字幕時刻

`--resume-from DIR --continue-missing`は完了済み応答を再利用し、未送信の工程だけを新規実行する。送信済みで完了不明の工程は再送しない。新規生成された工程はreceiptで区別する。

字幕本文と時刻を分け、区間音声だけと既存本文IDを使う`alignment-N`で発話時刻を照合する。本文は変更しない。参照音声の長さや元配信の開始秒との混同を防ぎ、時刻はなおGemini推定として記録する。発言が重なる表示枠は本文を両方保持して区間を統合し、話者色を通常色に戻す。原本応答は変更しない。

Actionsの`editorial_release`に保存済み応答の非公開Releaseタグを指定し、`continue_missing=true`で部分再開、`auto_render=true`で完了後にColab描画まで接続する。`config_file`は話題選定と描画の両方に適用する。
