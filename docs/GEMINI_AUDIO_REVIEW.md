# Gemini音声レビュー

このワークフローは、保存済みKick音声とParakeet ASRを入力として、Geminiの3段階レビューを新しい出力先へ各1回実行する。Kick取得とParakeet ASRは再実行しない。

1. Gemini 3.5 Flash / MINIMALで配信全体を逐語的に文字起こしする。
2. Gemini 3.8 Flash / MEDIUMで全文とParakeet時刻を見て、5分以上の切り抜き候補を5本選ぶ。
3. Gemini 3.8 Flash / MEDIUMで候補5本の音声を聞き直し、全文文字起こしと早口候補の査読を行う。

3.8 Flashの標準思考レベルはMEDIUM。HIGHは使わない。APIリクエストにはresponseMimeTypeやresponseSchemaを設定せず、65,536の出力トークン上限まで利用できるようにする。選定と査読の出力形式はプロンプトでJSONを依頼するが、APIの構造化出力機能で生成を制約しない。3.5全文とテキストだけの区間選定は同期generateContentで受け、採用音声の3.8査読はstreamGenerateContentのSSEで受ける。それぞれの生応答とusageを保存する。新Runでは3.5のSSE応答が音声未取得マーカーを返したため、過去に成功した同期方式へ戻した。

音声理解の上限に合わせ、1リクエストにつき音声ファイルは最大1つにする。全体音声は16kHzモノラルOpus、採用区間は保存済みM4Aから1回のFFmpegフィルター処理で切り出し、1秒の無音を挟んで1つのOpusファイルへ連結する。元音声と元ASRは変更しない。入力ファイルとHTTP本文は送信前にサイズ検査する。

各API呼び出しは自動再送・モデル変更を行わない。SSE受信イベントごとに途中応答、途中usage、応答ヘッダー、経過時間を非公開の作業領域へ記録する。接続断時は部分応答と例外内容を残し、応答がないusageやサーバー側の完了状況は不明と扱う。

早口候補は、Parakeetの発話区間で空白・句読点以外の文字数を区間秒数で割り、7以上の行から抽出する。この値は候補抽出の目安であり、Geminiには原音を聞いて候補全件を査読するよう指示する。修正は元の単語境界と時刻を保てる場合に限り字幕へ適用する。不確実な行は自動訂正しない。

`audio-editor-receipt.json`には各リクエストのモデル、思考レベル、HTTP状態、リクエスト/応答サイズ、音声ファイル数、usageMetadata、個別API経過時間とタイムスタンプを保存する。音声準備時間もAPI時間と分けて記録する。並列工程がある場合、個別時間の合計を実時間とは扱わない。Geminiの請求額はusageMetadataだけで断定せず、適用価格で別途計算する。

全体文字起こし、5区間の選定、採用部分の文字起こし、早口査読、生応答と時間記録は非公開Releaseへ保存する。査読結果を検証するまで動画描画を開始しない。動画全体の品質再走査、音量監査、査読を理由とした自動再描画は行わない。
