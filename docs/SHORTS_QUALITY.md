# 縦型ショートの編集設定と確認

0.3.0は画面合成・日本語字幕・確認記録を追加します。顔の自動追跡や追加の有料AI呼び出しは行いません。

## 黒帯をぼかし背景へ置き換える

```bash
clipforge cut source.mp4 --start 120 --end 159 \
  --framing blur-fit --height 1920 --caption progressive \
  --headline '親になって変わった話' \
  --transcript transcript.json --output outputs/short-001
```

9:16・高さ1920は1080×1920です。高さ1280は720×1280。従来の高さ720は404×720で、720×1280ではありません。
従来の黒帯は `fit`、中央切り抜きは `center-crop` で選べます。設定未指定時の既定値は `blur-fit`・高さ1920・`progressive` に変更しました。以前の設定ファイルで値を明示していれば、その値を保持します。

`cut` は文字起こしを行いません。`--transcript` の単語時刻は元動画の秒数で与えます。`run` は従来どおりFaster-Whisperで下書きを生成し、指定Geminiモデルで候補を選定します。

## ゲーム画面と顔ワイプの別配置

`config.streamer.example.json` をコピーして、自分の元動画に合う座標へ修正します。例の座標はサンプルで、動画を解析して得た座標ではありません。

```bash
clipforge cut source.mp4 --start 120 --end 159 \
  --config config.streamer.example.json --transcript transcript.json \
  --output outputs/streamer-001
```

- `presenter_region`: 元映像の顔ワイプ全体。顔だけを過度に狭く囲まず、表情・動きの余白を残す。
- `content_region`: ゲームを見せる領域。未指定なら元画面全体。元の小さいワイプがこの領域に含まれる場合は、それも映ります。必要に応じて領域を調整する。
- `x`, `y`, `width`, `height`: 回転補正後の元映像に対する0〜1の割合。出力先の座標ではありません。
- `stacked` は9:16専用。画面内容・顔・字幕・上部見出しの場所を分け、素材の縦横比を保持して収めます。
- 顔ワイプが移動する素材は区間を分けて設定するか、全画面表示で確認します。矩形の自動追跡はありません。

見せ場で顔を拡大する場合は設定に追加します。

```json
"punch_ins": [{"start": 145, "end": 146.3, "zoom": 1.25}]
```

時刻は**元動画の秒数**です。上記の120〜159秒を切り抜く例なら、出力の25〜26.3秒で拡大します。拡大率は1超〜1.6、区間は最大8個・重複不可。対象クリップと交わらない区間はそのクリップへ適用しません。元動画の範囲外はエラーになります。

顔の拡大は矩形の中央を切り抜く固定カットです。顔が元ワイプの端にあると見切れるため確認してください。元の顔映像の解像度以上の細部は復元しません。

## 字幕と見出し

- 日本語文節の候補をBudouXで求め、実際に解決した太字フォントをPillowで計測。2行以内・文末区切り・長い無音でカードを分けます。文字列は書き換えません。
- `progressive` は割り当てられた時刻まで後続文字と縁取りを透明にし、配置を動かさず順に表示します。SRTも同じ順序で表示されます。
- `plain` と `karaoke` はカード全体の文が先に見えます。オチの先出しを避ける用途では `progressive` を使います。
- ASRの長い単語を分割した箇所や単語時刻がない箇所は、文字数に比例した**概算時刻**です。`estimated_timing_spans` と `review_required` に残します。BudouXは音声を再アラインするツールではありません。
- `font` はインストール済みの正確なファミリー名を指定。未インストールのフォントは黙って代替せず停止します。文字欠けの可能性は `missing_glyphs` に記録します。
- `caption_font_scale` は高さに対する文字サイズ（既定0.036）、`caption_max_seconds` はカードを分ける長さの目安（既定2.8秒）。1つのASR単語そのものが長い場合は保持時間がこれを超えることがあります。
- `headline` は明示した見出し。自動選定では未指定時に選定タイトルを使用。手動切り抜きで未指定なら見出しなし。`show_title: false` で非表示。
- 見出しは黄色・黒縁で上部2行まで。長ければ段階的に縮小し、それでも収まらなければ短くするようエラーを返します。
- 安全余白は初期レイアウトです。投稿先アプリのUI配置を保証する値ではないため、投稿プレビューで確認します。

## 書き出し時に確認すること

MP4の縦横サイズ・長さ・映像/音声トラック数を確認し、**全体をデコード**して破損を検査します。顔パネルを増やしても音声は複製しません。音声ありの場合は従来のloudnorm（目標−16 LUFS／−1.5 dBTP、1パス）で調整し48kHz AACへ出力。目標値は書き出し後の実測値ではなく、SNSの必須仕様でもありません。

`render.json` と `manifest.json` の各クリップに、適用した元領域・切り抜き基準の拡大時刻・フォント・要確認事項を記録します。例：

- `estimated_caption_timing`: 字幕時刻の概算を含む。
- `clip_boundary_inside_asr_token`: 単語の途中が切り抜き端に重なる。
- `font_missing_glyphs`: 指定フォントにない文字がある。
- `forced_line_break`: 文節を保持したままでは横幅に収まらない箇所がある。
- `presenter_upscaled_over_2x`: 小さな顔素材の大幅拡大。

元動画を上書きしません。書き出し・字幕作成・全体デコードが成功するまでクリップを確定しません。設定・実装・入力が変わった場合は新しい出力先を使います。

## 最後に目と耳で見ること

1. 冒頭で誰の何の話か分かるか。見出しが発言の意味を変えたり、オチを明かしたりしていないか。
2. 字幕の誤字・固有名詞・文節・発言との同期。概算時刻の箇所は特に確認。
3. 顔・ゲームの重要な情報・字幕が重ならないか。拡大区間の前後も見る。
4. ミュートで意味が通るか。小音量で声が聞き取れるか。混合済みのゲーム音と声の比率は音量正規化だけでは直らない。
5. 最後のリアクションや笑いを切っていないか。

`human_review_performed` は自動処理で true にしません。技術検査の合格と、実配信素材の品質・視聴維持率の評価は別です。

## 回帰確認

```bash
uv run --no-sync python -m unittest discover -s tests -v
```

`.github/workflows/quality.yml` はGitHub-hosted CPU runnerで、生成したテスト素材だけを使って1080×1920のぼかし背景・2段合成・拡大前後を描画。旧レイアウト、無音、横長/正方形、非ゼロ開始、再開、字幕変更時の再利用拒否、全体デコードも確認します。`shorts-quality-review` ArtifactにMP4・比較画像・JSONを3日間保存。ユーザーの動画をこの公開ワークフローへ入れません。

確認用素材には本物の会話がなく、テスト音と生成画像だけを使用します。実配信の音声認識・感情に合う演出・移動ワイプ・Gemini選定品質の評価にはなりません。
