# 納品前の見直しの方針

目的は、全部を同じ強さで見ることではなく、誤りが出やすい箇所を確実に見ることです。全件を見ていない場合は、その範囲を納品メモに書きます。「全件確認した」とは書きません。

## 1. 必ず等速で見る箇所

1. **語を変えた行**（清書で語が変わった行）。音声と照合します。
2. **話者交代の行**（水色の行）。話している人が本当に変わったかを確かめます。
3. **数字・金額・日付・人名・店名・ゲーム名などの固有名詞**。
4. **断定の語と結論**（「絶対」「確実」「100%」「必ず」「〜だけ」、オチ）。
5. **見出しと字幕の内容の一致**。見出しが、動画の内容の根拠を超えていないか。
6. **各クリップの冒頭 30 秒と末尾 30 秒**（切り出し境界、話題の始まりと終わり）。
7. **0.5 秒以上の無音をまたぐ字幕**（字幕が残りすぎていないか）。

## 2. 流れで見る箇所（2〜3 倍速でよい）

- 字幕の流れ、字幕の出る位置、画面の外に出ていないか。
- 1 行の長さ（目安 18 字）と、2 行を超える字幕（目安を超えていないか）。
- 「？」だけの変更（記号のみ）は、一覧で数と位置を確認する。文の種類が変わるため、一行ずつ判断する。

## 3. 抜き取り

- 語を変えていない行から、クリップごとに無作為に 10 行を等速で確認する。
- 抜き取りで誤りが 1 行でも見つかったら、そのクリップは全行を見直す。

## 4. 順番

- 語を変えた行が少ないクリップから、2 本ずつ確認する。
- 確認表は、クリップごとに、必ず見る箇所（1 の 1〜2）を先頭に並べる。

## 5. 経路ごとの確認（納品前）

| 経路 | 確認すること |
|---|---|
| 取得 | 元配信と同じ長さで、音声が最後まで取れているか |
| 話題選定 | 各話題の始まりと終わりが、話の区切りと合っているか。尺は目安の 5〜15 分か |
| 文字起こし | 窓の境界で、同じ語が 2 回出ていないか（重複整理は、同じ話者、完全一致、重なりが短い方の 70% 以上の場合だけ） |
| 清書 | 1〜3 の見直しに従う |
| 描画 | 字幕が画面外に出ていないか、2 行を超えていないか、字幕と声の時刻がずれていないか |
| 回収 | 件数（5 本など）、尺、zip の内容が転送記録と一致するか |
| 納品 | 配信者の許可を確認しているか。宛先は指定のものだけか |

## 6. 記録

- 納品メモに、確認した範囲を書きます。
  - 例：「語を変えた行は全件、話者交代の行は全件、抜き取り 10 行 × 5 本を確認」
- 確認していない行は、「確認済み」にしません。

## 7. 今のセッションでの制約

- 確認用パッケージと完成物の回収は Release の REST API を使い、asset のサイズを照合します。完成物はさらに転送記録とファイルの同一性を照合します。接続の拒否は別アカウントや別経路で回避しません（[OPERATIONS.md](OPERATIONS.md)）。
