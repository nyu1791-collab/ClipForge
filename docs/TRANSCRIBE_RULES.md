# Gemini 3.5 Transcribeの設定と運用ルール

この文書はTranscribeへの自由文プロンプトではない。対応する設定は `src/clipforge/transcribe_pipeline.py` の `transcription_config()` に定義し、リクエストと保存結果の識別に同じ値を使う。根拠: [Google Cloud Transcribe](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-5-transcribe) と [GenerateContentの仕様](https://ai.google.dev/gemini-api/docs/generate-content/transcribe)。設定によって精度が保証されるわけではない。

- 日本語 `ja-JP`、`VERBATIM`、単語時刻、話者分離を指定する。フィラーや相槌を機械的に削除しない。単語時刻と話者分離は推定で、短い声や重複発話の取り違えもあり得る。
- `SMART` と単語時刻・話者分離は併用しない。カスタム語彙も単語時刻・話者分離との併用は指定しない。音声から聞こえない固有名詞を文脈だけで補わない。
- 各採用話題を対象とし、Transcribe音声窓は最大898秒、隣接窓は2秒重ねる。通常15分未満の話題は1回だが、898秒を超える場合は分割する。境界は重なりの中央で担当を分け、前後の時刻をクリップ内の時刻に戻す。隣接窓で文字が完全一致し、時刻が十分重なる長めの語だけ重複を除く。短い相槌や曖昧なものは残す。境界で認識が揺れると欠落・重複が生じ得る。
- モデル出力の話者ラベルはリクエスト内だけで扱い、別窓の同じラベルを同一人物と決めつけない。Flashが同じクリップの音声を聞いて判定できない場合はunknownとする。
- 空白補助（15秒以上の字幕空白に対する追加のTranscribe要求）は現行の経路から外した。空白の音量は発話判定に使わず、用語調査と同じく保存データにも追加要求を作らない。
- 単語時刻が得られないテキストを別途保存し、時刻を創作しない。現状はそのテキストを時刻付き字幕として表示できない。認識された単語が存在しない発話をFlashが自動で復元することも保証しない。
- 最大6話題を並行し、各話題でTranscribeの完了後に3.5 Flash/MEDIUMの整文を1回開始する。描画可能な話題は他を待たずにGPUへ送る。長い話題では分割数に応じてTranscribe要求が増える。APIやGPUの待機時間・速度向上は保証しない。
- 途中の入力・応答は非公開に保存し、入力識別が一致する完了済み応答だけを再利用する。通信障害・429・5xxは同一要求を合計3回まで、その他HTTPエラーは再送しない。成否不明の再送に伴う重複課金はあり得る。素材取得・ワークフローの自動再投入はしない。
- 整文では原音と文章を使用し、要約せず意味・順序・口調を保つ。文脈上意味がある「うん」「いや」「まあ」や反復を単語リストで一律削除しない。文章の文字が完全に同じか句読点・空白だけの変更であれば元単語時刻を引き継ぐ。それ以外は既存の発話範囲に戻し、単語単位の同期を保証しない。
- これは品質の目標であり、字幕網羅率や話者数を合否判定して制作を止める仕組みではない。認証・媒体・保存先の誤り等の実行不能エラーは別に記録する。
