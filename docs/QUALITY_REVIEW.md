# 品質確認の記録

現在有効な決定事項と取り消しは [QUALITY_DECISIONS.md](QUALITY_DECISIONS.md) を参照してください。このファイルは実行・計測の記録です。

対象は切り抜きCLI、候補抽出、Gemini SDK接続、字幕、再開処理、非公開Actionsと制御VMの連携です。
2026-10-21にユーザーから全体確認の依頼を受け、回帰テストと実動画の検査を追加しました。

## 見つけて修正した問題

- **Geminiの呼び出し前に停止**：Pydanticの `exclusiveMinimum` がGoogle SDKのSchemaに拒否されていました。Google用の明示スキーマに変更し、応答は引き続きPydanticでも検査します。公式SDKを通して実際のHTTPリクエストを組み立てる、通信先を模擬したテストを追加しました。
- **失敗後も古い完了表示が残る**：手動切り抜きの再開に失敗すると前回の `complete` が残っていました。実行中・失敗・完了を明示し、失敗段階と安全なエラー理由を記録します。
- **壊れたキャッシュ記録で再開不能**：破損したJSONを完了結果として採用せず、その段階を再計算します。
- **短い動画の候補が消える**：発話境界への調整で最低尺を割り込んだ場合、元の有効区間へ戻します。
- **候補が冒頭へ偏る**：同点の候補は各時間帯の中央へ分散するよう調整しました。
- **描画中の元動画変更を検知しない**：送信前と出力確定前に元のSHA-256と照合します。
- **プレビュー作成失敗時の残存**：作成途中も含めて後処理で削除します。
- **出力先のシンボリックリンク**：出力ディレクトリとその親のリンクを拒否します。
- **空の入力**：処理開始前にサイズで拒否します。
- **再利用する出力の検査順**：ファイル名の集合を先に検査し、予定外のパスを読みません。

## 自動検査

- 単体：モデル・区間検査、字幕の時刻とレイアウト、候補抽出、キャッシュ、再開、失敗処理、SDKのJSON化、API拒否時の再試行禁止、ログの秘匿。
- 動画：自作の36秒の合成映像・音声を使用。3つの場面の境界は既知で、13秒時点の画面は赤です。
- 実エンコード：縦・横・正方形、余白追加・中央クロップ、音声の有無、字幕、入力維持、再開、実際に復号した画素と尺を検査します。
- 実ASR：CPU/int8の `tiny.en` で音声認識と単語時刻を確認し、手動選定を含む通し処理を確認します。
- CI：Python 3.11 / 3.12、単体カバレッジ90%以上を合格条件にします。通常CIは外部LLMを呼びません。

ローカルのPython 3.12で114件の単体テストが通過しました。実動画のCI、VM経由の依頼・回収、実Gemini呼び出しの結果は確認後に追記します。

## 字幕・音量の自動検査（追加分）

- 字幕の読み速度：1秒あたり10文字を目安に、次の字幕までの無音へ表示を延ばします。15文字を超えて残るものは警告です。
- 品質ゲート：`quality.json` に字幕の重なり、フォントにない文字、出典・ライセンス欠落、EBU R128の統合ラウドネス（−16 LUFS ±1 LU）と真ピーク（−1 dBTP以下）を記録します。`quality_gate=strict` では失敗のあるクリップを確定しません。
- 映像：画像・図解の出入りに `fade_seconds` のフェードを掛けます。

確認結果（ローカルのPython 3.13、ruff 0.14.14の固定版）：
- 単体テスト286件が通過、カバレッジ96%（CIの合格条件は90%）。整形と静的検査は通過。
- 統合テスト9件（自作の合成動画）と音声認識テスト2件（`tiny.en` と日本語の `small`）が通過。
- 実動画の通し処理（音声認識のみ保存済みの文字起こしで代替）：2クリップとも完了。両方とも−16.0 LUFS、真ピーク−1.4 dBTP、失敗なし。字幕の読み速度の中央値は8.1・7.2字/秒。
- 残る警告：1クリップに16.7字/秒の字幕が1件あります。切り抜きの最後の語（3文字・0.18秒）で、音声がそこで終わっているため延ばせません。
- 画面確認：フェードイン・フェードアウトの途中のフレームで、画像が半透明に変わることを目視で確認しました。

音声認識は保存済みの文字起こしで代替したため、認識精度そのものはこの確認の対象外です。

## 品質確認の意味と限界

合成動画で時刻・字幕・処理経路を確認しても、実際の配信の面白さや日本語認識精度を保証するものではありません。
人の確認前に自動公開せず、実際に扱う素材で、会話の文脈・固有名詞・字幕の見た目を確認する必要があります。
Geminiの無料tier・割当・APIの稼働状況は、テスト結果とは別に扱います。

- **スレッド数**: 既定の 2 を 4 に変える案を試したが、取り消した。4 スレッドで文字起こしが速くなる根拠は得られず（同じ抜粋で 155 秒 対 95 秒。2 スレッドの方が速く出た）、計測のばらつきが大きいと判断した。既定は 2 のまま。

## 用語の綴り・文末の区切り・字幕ツールの確認（2026-10-22）

- **用語の綴り**：単語ごとの辞書を `ai`・`agi`・`asi` から、`chatgpt`・`openai`・`ollama`・`gpu`・`cpu`・`api`・`llm`・`youtube`・`gemini`・`claude` などへ広げた。`Kick` は英語の一般語と紛れるため入れていない。
- **2語の用語**：`LM Studio`・`Hugging Face`・`OpenAI`（`open ai`）・`ChatGPT`（`chat gpt`）などは、隣り合うトークンが完全に一致したときだけ1つにまとめ、開始は最初の語、終了は最後の語の時刻を使う。句読点が付いた語は一致させない。
- **実動画での確認**：文字起こし（4194語）で、この用語の変換は0件だった。この動画に該当する語がないため。英字の断片（`A`・`GI`、`AS`・`I`、`R`・`SI`、`You`・`T`・`uber`）は、字幕では空白なしで連結されるため表示は正しく、語の途中の改行は既存の規則（英数字どうしは改行しない）で防げている。
- **文末での区切り（不採用）**：文末の句読点で字幕を区切る処理を試したが、字幕の統計は1件も変わらなかった。文字起こし4194語のうち、句読点で終わるのは2語だけで、入力がないため効果がない。効果の測れない処理は複雑さだけを増やすため取り除いた。
- **課題として記録**：この文字起こしは句読点をほとんど含まない（`large-v3-turbo` の出力）。字幕の区切りは、今のところ無音と語の境界に頼っている。句読点の復元や、語尾（です・ます）と間による区切りは、別に計測してから判断する。
- **フォント幅**：`fonts.Measure` は Pillow の `ImageFont.getlength`（字の進み幅）で測っている。字幕の横幅の検査はすでに Pillow で行っている。インク範囲の `getbbox` に替える利点は小さいと判断し、変更していない。
- **字幕ツールの確認**：`budoux` は `captions.parser()` で既に使用中。`pysubs2` も既に使用中。`stable-ts` は未評価（導入すると重い依存が入る可能性があり、効果の計測が必要）。Whisper の `initial_prompt` による用語の指定は未評価（文字起こしの結果が変わるため、再実行と計測が必要）。

### 文末の判定を形態素解析にした

文末は、形態素の品詞で判定する。です・ます（どの活用形でも）、だ（終止形）、た（終止形、かつ直前が です・ます・だ）、終助詞（ね・よ・か・な など）。後に助詞・助動詞が続く場合は文が続くとみなし、区切らない（「です｜よね」を防ぐため）。その字幕が1秒以上続いていれば区切る。

15分の実動画（`e2e-final4` の文字起こし、同じ設定）で比較：

| 指標 | 丁寧語の正規表現（858d303） | 形態素（今回） |
|---|---|---|
| 字幕数 | 57 | 57 |
| 1秒未満の字幕 | 2 | 1 |
| 中央値の表示時間 | 2.04 秒 | 2.04 秒 |
| 字幕の先頭が終助詞で始まる（孤立した終助詞） | 6 | 1 |
| 字幕の先頭が助詞・助動詞で始まる割合 | 30%（17/57） | 19%（11/57） |

- 字幕の末尾が形態素の文末になる割合は、どちらも 33%（19/57）。丁寧語の規則は「です」で切るため末尾が「ね・よ」になりやすく、この指標は改善を示さない。改善は、孤立した終助詞の減少と、口語の語尾への対応による。
- 試して採らなかった案：ポーズ（0.3秒以上）を必須にした版は、丁寧語の区切りまで減った（末尾の割合 4%）。助動詞の終止形を広く取った版は「〜たい」「〜ない」で誤って区切った。
- 「てる」「じゃん」などは、この1本では判定に入れていない（「てる」は文中にも現れるため）。「だった」「ちゃった」は、後ろに接続詞などが続く場合に判定される。この1本には該当がないため効果は未検証。
