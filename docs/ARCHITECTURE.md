# 構成と実装順序

```text
入力動画
  → FFprobeで長さ・ストリーム情報を取得
  → 時刻付き文字起こし
  → AIによる候補区間・理由・タイトルの提案
  → 区間の妥当性確認・必要に応じた人の修正
  → FFmpegによる切り抜き・画面調整
  → 字幕編集・焼き込み
  → MP4 / SRT / ASS / 区間JSON
```

初期実装は入力ファイル1本・明示実行1回に絞る。URLからの取得や各サイトへの投稿は後続の独立機能として扱う。

## ディレクトリ

- `src/clipforge/`: 今後のPython実装。
- `docs/`: 構成・実行記録。
- `inputs/`, `outputs/`, `artifacts/`: 実行時に作る私有ディレクトリ。Gitの対象外。
- `.github/workflows/`: CPU runner上の手動ビルド。生成・レンダリングは今後追加する。

## 処理の分担

- 時刻付き文字起こし: faster-whisper（CPU）。字幕の時刻もこの工程で管理する。
- 見どころ選定・タイトル案: Gemini API。まず文字起こしテキストと時刻だけを渡し、動画全体は送らない。
- 切り抜き・縦動画化・字幕焼き込み: FFmpeg。

映像を見ないと判断できない動画（ゲーム・スポーツ・実演など）だけ、動画や候補場面の画像をGeminiへ渡す。その場合は送信量・料金・動画の取り扱いを事前に確認する。
Geminiの提案時刻はずれることがあるため、字幕と実映像で照合してからFFmpegで切り抜く。

## モデル経路

Gemini APIを候補選定の第一候補とする。実装時に、入力形式・送信対象・返す区間のスキーマを決める。
他の無料モデルやClaude/Argonは、既存の非公開 `ai-model-workers` と制御VMの `ai-models` 経由で利用する。
公開リポジトリの `GITHUB_TOKEN` は、非公開workerの横断権限を自動的には持たない。
制御VMが所有者権限で依頼し、指定された資料だけを渡す。

## 開発段階

1. 基盤・権限・APIキーの登録（完了）。
2. 明示した開始・終了時刻での切り抜き（実装済み。合成動画で手動確認のみ。実動画とActions runnerでは未確認）。
3. 時刻付き文字起こしと字幕出力。
4. Geminiで候補場面を選び、2と3へ接続。
5. 実動画1本で端から端まで確認。
6. 実行上限・重複防止・失敗通知を備えた定期運用。

現在は段階2まで。段階3以降を実装済みと扱わない。
