# 査読への対応と未対応（2026-10-23）

査読の優先度順に、対応の有無と理由を記録する。対応済みの項目は、テストで確かめている。未対応は次の作業に残す。

## 対応済み

| 優先度 | 項目 | 対応 |
|---|---|---|
| 1 | Colab成果物の回収停止 | PR #14 の変更（診断ファイルを検査一覧に含める）を取り込み。回収側の検査は維持 |
| 2 | 品質ゲートと納品条件 | 音量（−17〜−15 LUFS）と真ピーク（−1 dBTP 以下）を不合格にした。字幕の速さ・重なりなどは警告のまま |
| 4 | 取得上限の不一致 | プレビュー・描画の取得上限を設定値 `max_transport_bytes` に統一（固定の2 GiBをやめた） |
| 5 | GPUのバッチ処理 | GPUで `asr_batch_size` > 0 は設定の検査と認識の直前の両方で拒否 |
| 6 | ASRの記録 | 描画環境に固定値 `cpu/int8` を記録しない。設定が要求する認識条件を `asr_compute_requested` に記録 |
| 9 | プレビューの順位 | 文字起こし・発話・音量のヒントで順位を付けてからプレビューを取得（発話量だけで決めない） |
| 12 | 依存の脆弱性 | `curl-cffi` 0.13.0 → 0.15.0（修正版）。公開情報の脆弱性 CVE-2026-33752 に対応。`uv.lock` とハッシュ付き一覧を更新 |
| 3（一部） | Geminiへの送信量 | 候補の動画の合計バイト数（1 GiB）と本文の合計文字数（50万字）を、アップロード前に確かめる。上限は大きめ |
| 14（一部） | README | GPU経路の対象（Kick）と、2〜4部分の説明を現行に合わせた |
| 13 | worker配備の対応表 | `deploy/` の7本は ai-model-workers の対応ファイルと内容が一致（ClipForge HEAD の blob で比較）。ワーカー専用は `clipforge-colab-oauth`・`clipforge-colab-status`・`model-worker` の3本で、`deploy/` の対象外 |

## 未対応（理由つき）

| 優先度 | 項目 | 理由・次の作業 |
|---|---|---|
| 3（残り） | Gemini入力の全面的な予算管理 | Gemini は既存の選定経路（ローカル動画）だけで使う。GPU経路の対象外。 |
| 7 | 無音検出のVAD統一 | silero は任意機能で、既定は文字起こしの側を使う。既定経路に影響しないため、統一は後回し。 |
| 8 | 設定・依頼・承認・receiptの契約の共通化 | 大きな改修で、今回の対象外。次の大きな作業として計画する。 |
| 10 | 字幕検査（PR #9）の接続 | PR #9 は caption_review.json を要求し、現行は quality.json。接続の設計が必要。 |
| 11 | PR #8 の機能移植 | 二重のパイプラインになるため、必要な機能を個別に移す。尺・重複の仕様は横動画の方針に合わせる。 |
| 2（準備） | 割り当て前の準備・プレビューの短縮 | 音声取得は、並列数（6→12）では縮まなかった（39.6秒→37.8秒）。音声の符号化（CPU）が律速。`fast` 符号化は文字起こしを変えるため不採用。 |
