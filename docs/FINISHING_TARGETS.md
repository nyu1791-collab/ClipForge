# 字幕・音・描画の仕上げ目標

以下は仕上がりを整えるための目安。合格基準・停止条件ではない。少し外れたことや補助処理を適用できなかったことを理由に、strictエラー・追加モデル要求・自動再生成・監査へ進めない。

| 対象 | 落とし込む工夫と目安 | 判断しにくい・目安に届かない場合 |
|---|---|---|
| 字幕要求の単位 | 採用話題ごと1回。60秒の継ぎ目を新規に作らない | 話題全体を一文に要約せず、元の発話順と自然なsegmentを保持する |
| 句読点と区切り（目安） | 字幕本文に句読点（、。）を使わず、言葉の間は全角スペースで区切る | 出力に句読点が残っても制作は止めない。現状の出力には残る場合があり、描画側での除去は未実装 |
| 字の色（3色・目安） | 白（通常）・黄（強調）・水色（別の声）。水色はTranscribeの話者ラベルの違いで決め、判定はしない | 描画側は現行で話者ごとの色を使うため、3色への切り替えは未実装 |
| 字幕の時刻 | 採用音声のTranscribe文字起こしが返した発話時刻を使用する | 清書後の単語精度は保証せず、時刻のずれだけで停止・再生成しない |
| 日本語の改行（目安） | 1行は13〜18字を目安に、文節の区切りで分ける（原則1行、長いときだけ2行）。句読点（、。）は使わず、区切りは全角スペースにする | 目安に届かなくても制作は止めない。文節を崩す切り方より、文節を優先して残す。切れない長い語は表示できる折り返しを使い、文字は削除しない |
| 短い字幕（目安） | 同じ話者の自然なまとまりを作り、読み速度は1秒4〜5字を目安にする。表示時間の下限の目安は0.8秒程度。延長処理の目安は0.8秒。※現行コードは読み速度の目標10字/秒（captions.py）、グループ化の最短1.0秒（caption_breaks.py）で、上記の4〜5字/秒・0.8秒とは未整合（要判断・未変更） | 目安同士が合わないときは、意味の区切り・1行の目安を優先する。次の発言・話者交代・クリップ末尾を優先し、余地がなければ短いまま表示する |
| 無音での居残り | 元発言の終了からの読み取り用延長は最大約1.5秒。無音が0.5秒以上続く箇所では、その手前で字幕を消す（目安） | 発話そのものが長い場合を「1.5秒で切る」処理にはしない。次の字幕より後へ延長しない |
| 切り出し | 初回選定時に開始−0.3秒・終了＋0.5秒程度の余白を取り、元配信の範囲内へ収める | 元配信の冒頭・末尾では取れる余白だけ使う。尺や重複の目安を理由に拒否しない |
| 会話の音量 | 描画内の1パスloudnormの目標をI=−14 / TP=−1.5 / LRA=11とし、既存の保守的なリミッターを維持する | 出力の実測値の達成を保証せず、未達による再測定・補正・再描画は行わない。YouTubeの一律必須規格とは扱わない |
| 効果音 | 現行の清書では効果音を指示しない。描画側の効果音処理は、修正パッチで指示が与えられた場合だけ働く | 効果音の数・聞こえ方で品質不合格にしない |
| 文字の解像度 | 素材は最大360p取得を維持。通常は360pへ字幕・見出しを焼き付け、指定時は720p/1080pキャンバスを使う | アップスケールで元映像の細部が復元したとは報告しない。360pを選んだことを品質エラーにしない |
| 見た目の参考画像 | 描画済み動画から通常字幕・強め演出など実在する最大3場面を抜き、クリップごとの一覧JPEGを作る | 演出のない動画に見本を捏造しない。画像生成・単体画像アップロードができなくても動画の保存を続ける |
| 修正・再開 | 保存済み字幕・時刻・演出への明示パッチを、共通render-onlyへ渡す | 修正済みの時刻へ余白追加を再適用せず、Geminiへ戻らない |

## 補助処理と実行エラーの区別

重複整理は隣接する窓の境界だけに限定し、一定以上の長さ・時刻の重なり・本文の包含・類似度に加えて、話者・数字・否定の違いを見て保守的に行う。別の発言かもしれない場合は残す。「全編の反復削除」は復活させない。

元の発話時刻は採用区間のTranscribe文字起こしから引き継ぐ。清書後の単語時刻精度・強制アライメント・リップシンクの達成は保証せず、追加の時刻照合モデルや完成映像の検査を行わない。

もともと重なっていない隣接字幕は、直前字幕の補正後の終了時刻も考慮し、補助処理によって新しい重なりを作らない。元からある同時発話は、この処理で無理に解消しない。

切り出し余白は選定時に一度だけ加え、元の選定時刻と余白後の時刻を `clip_safety_margins` に残す。その余白込み音声から字幕を作るので、字幕・話者・SEの時計も同じクリップ先頭へそろえる。保存済みの編集データを描画するときは、選定・余白・重複整理・波形補助を繰り返さない。

元素材不存在、認証/通信失敗、実際の描画失敗、壊れた媒体、素材や保存先の取り違えは、補助処理の未達とは別の実行エラー。成功と偽らず記録する。参考画像だけの失敗は、完成動画の失敗へ昇格させない。

## 解像度と参考画像の扱い

通常CLIの `--render-profile preview|standard|full-hd` は、それぞれコミット済みの360p/720p/1080p設定を選ぶ。省略時は `config.landscape-long-preview.example.json` の360pキャンバス。`--config-file` で別の設定を選ぶこともできる。両方指定した場合はrender-profileが設定ファイルを選ぶ。高解像度の素材を自動取得する指定ではない。

描画後の `contact-sheet.jpg` は見た目の修正を助ける参考資料で、自動監査結果ではない。全編を検査用に再デコードせず、既に生成した字幕イベントの時刻へ限定して最大3フレームを読む。時刻と実際のスタイル名を添え、見出し・色・文字の大きさを見比べられる形にする。字幕全文・同期・固有名詞の正しさを、この画像で確認済みとは扱わない。

画像は非公開result.zip内に保存する。可能なら同じ非公開Releaseへ `clip-001-contact-sheet.jpg` 等の単体assetも追加し、動画zipを回収せず画像だけ取得できるようにする。単体assetの追加に失敗しても、動画とアーカイブの保存成功を維持する。品質のpassedは引き続きnull、監査はnot_run。

コード更新だけを理由に、既存の完成動画を作り直さない。

通常制作・修正・回収の入口は [統合経路ガイド](PRODUCTION_AND_REVISION.md)。Geminiへ渡す表現は [必読編集ルールブック](../src/clipforge/prompts/gemini_editorial_rulebook_ja.md)を参照。
