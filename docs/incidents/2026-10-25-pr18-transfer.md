## 実装

`clipforge.release_transfer`を標準ライブラリだけで起動できるCLIとして追加。

```sh
python -m clipforge.release_transfer publish "$RESULT_DIRECTORY" "$RESULT_NAME"
python -m clipforge.release_transfer download "$GITHUB_RUN_ID" \
  "clipforge-analysis-$REQUEST_ID" "$RUNNER_TEMP/clipforge-analysis"
```

非公開workerリポジトリだけを許可。タグは`clipforge-{analysis|result}-REQUEST_ID-run-RUN_ID`。
`result.zip`と`transfer.json`の2アセットを保存する。既存タグを上書きしない。
別プロセスがリモートから再取得し、期待マニフェスト、receipt、全ファイルのサイズ・SHAを照合して初めて`RESULT_VERIFIED`を出す。
同一タグの内容が違えば失敗する。途中まで作られたReleaseも成功扱いにせず、手動調査が必要。

ZIP直下を工程のルートとして復元。親ディレクトリの推測や欠損ファイル補完は行わない。
絶対パス、`..`、リンク、重複、特殊ファイル、既存出力との衝突を拒否する。
workerの前段取得、part取得、制御側collectもReleaseを優先する。
Releaseが存在しない場合だけ旧Artifact取得を許可し、既存の工程別検証は維持する。
壊れたReleaseからArtifactへは切り替えない。

転送上限は1,900 MiB、2,000ファイル。現在は単一ZIPで、上限超過を明示的に拒否する。
大きな1080pバッチなどには分割転送の追加が必要であり、無制限対応ではない。

`github_cli`を再び`-m`で誤用した場合も非0終了する。

書き込みを拒否された状態で別認証や別経路へ切り替えていない。
