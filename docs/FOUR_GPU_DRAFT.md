# 4 GPU並列化の作業案

このブランチは作業案であり、テスト・実GPU検証・本番反映はしていない。

- 採用話題をクリップ番号の剰余で最大4組へ分配し、それぞれ別のColabランタイムで文字起こしする。
- 字幕整文は60秒に分割せず、1話題1回の要求を最大5件並列に実行する。要求と時刻の記録は話題別に残す。
- 通常制作の描画も最大4組に分配し、1つのGPU内では最大2本のクリップを同時に描画する。GPUのセッション数・メモリ・CPU・ネットワークによって失敗や低速化もあり、速度は未測定。
- 各クリップの描画後すぐに個別の非公開Releaseへ保存する。制御側はその記録を監視して、完了本数・クリップ番号・描画時間をActionsログに出力する。
- 話題またはクリップが4件未満の場合は、その件数が並列数の上限となる。単一の話題・クリップは分割しない。
- render-onlyの既存経路は並列化していない。
- 描画の一部が失敗した場合は、保存済みクリップを部分結果Releaseにもまとめる。明示的なrender-onlyの `--reuse-render` で一致するクリップを再利用できる設計。送信・実行が不明な要求は自動再送しない。ASRの未完了部分を自動で再送・復旧する機能はない。
- 部分描画の依頼マーカーと結果Releaseは再送防止・復旧のため保持する。後片付けの手順は未整備。
- GPU割当数はColabの実際の容量に左右され、4台の確保は保証されない。

採用前には、同一性、並列時の要求記録、GPU解放、部分失敗・中断からの復旧、保存と統合、実際の割当とNVENC並列数を含む検証が必要。
