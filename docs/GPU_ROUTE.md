# 通常制作の正本：Parakeet → GPU/NVENC

ユーザーの2026-10-25の指示により、制作時のstrict品質検査を廃止する。完成映像の検査用全デコード、LUFS・True Peak測定、品質ゲート、それを理由にした音声補正・再描画は行わない。未実施の検査を「合格」と記録しない。

| 段階 | 処理 | 場所 |
| --- | --- | --- |
| 1 | URL・設定・依頼IDを確定し、保存済み入力があれば再利用 | 制御側 |
| 2 | 音声取得、16kHz mono WAVへ復号、静かな位置で4分割 | runner |
| 3 | T4/L4最大4台でParakeet | Colab GPU |
| 4 | 結果を元時刻へ結合して話題分け。全文を字幕と共用 | runner |
| 5 | 保存済みASRからVertex Geminiが長い話題を選び、区間・見出しをJSONへ保存 | runner |
| 6 | 1台のGPU/NVENCで5〜10本を順次描画。次の素材を先行取得 | Colab GPU |
| 7 | 完成MP4・字幕・描画記録を回収して非公開納品 | 制御側 |

通常は360p、16:9は640×360。指定時は1080p。既定は5本、各300〜900秒。話題の最小長も300秒とし、短い話題を量産しない。素材取得・先行取得は最大360pの通常経路を維持し、NVENCがなければCPU映像描画へ黙って切り替えない。Whisperへの自動変更も行わない。

通常描画は `submit_audio_stage.py --stage render --clips N --config-file config.landscape.example.json --source-ref FULL_SHA --previous-run RUN --previous-request ID --review-file /private/approved.json`。`--clips N`は採用本数と一致させる。workflow refと制作ソースの40桁SHAは区別する。

制作設定の`quality_gate`は`off`。過去の依頼JSONを読むため`strict`と`report`もパースできるが、制作経路では品質監査を呼び出さない。新しい成果物に`quality.json`を生成しない。描画記録のqualityは`status=not_run`、`passed=null`とする。過去の成果物に含まれる検査記録は過去の実行結果として読み取れる。

音声の通常補正は描画内の1パスloudnormとリミッター。完成AACの再測定・補正・再検査は行わない。

工程の開始・終了、実時間、GPU準備、素材取得、先行取得待ち、エンコード、保存・回収・納品時間、失敗回数は記録する。並列の内訳を足して実時間にしない。未計測の値はnullで、0秒としない。

ユーザーがやり直し不要と指示した場合、失敗は記録して終了し、自動で再投入しない。既存の音声・ASR・完成物は再利用し、同じ配信の再取得・再認識を繰り返さない。

検証ブランチで作業し、mainへのマージや公開はしない。

## 追加処理の削減

通常経路はASR本文から候補を作る。全音声RMS解析、候補チャット取得、候補映像の先行生成、画像一覧作成、video_reviewed承認ゲート、字幕配置の映像サンプリングは行わない。caption_lift=false。YouTube/Twitch/Kick/直接HTTPSのURL経路は維持する。

ASR各部分は1回のみ。失敗時の別GPUでの再認識は行わない。GPU確保の待機上限は0秒で、候補を一巡して確保できなければ停止する。Kick通信も1回のみ。GPU解放と処理済み成果物の保存・工程時間記録は行う。

納品は新しいフォルダへの1回の転送とし、完成動画の全量読み戻し監査は行わない。転送APIの返したファイル情報を記録し、読み戻し未実施を明示する。

## 準備・転送を統合した通常経路

result_storeはreleaseが既定。描画GPUが最終Releaseへ直接ZIPを1回アップロードし、Actionsはtransfer.json内の実行記録だけを受け取る。ActionsでMP4を再取得・再梱包・再アップロードする工程は置かない。回収端末／Driveが必要な時点で初めて本体を取得する。

保存直後の別プロセスによる全量読み戻し、アーカイブの追加SHA走査、再取得後の全ファイル再走査は行わない。状態はRESULT_UPLOADEDとして記録し、実施していない検証をRESULT_VERIFIEDと呼ばない。依頼IDと保存先を結び付ける小さな実行記録と、通常のファイル展開処理は使用する。

ColabのOSツール＋Node準備とPython環境構築は並列実行する。YouTube/Twitch対応のmedia-fetchとNodeは維持し、チャット表示用extraはchat_panel=trueの設定時だけ導入する。

ASR等の既存分割転送はtarを直接チャンクへ書き、巨大な中間bundle.tarを作って読み直す工程を置かない。

Driveは設定済み認証で保存先を作ってからMP4本体を取得する。プロフィール照会、フォルダ権限監査、保存後読み戻しは行わない。保存先作成に失敗した場合は大容量動画を取得せず終了する。失敗後の再試行なし。

この改修後の実動画による速度再計測は未実施。削除済みのASR再利用・監査なし・承認待ちなし・自動再生成なしの方針を維持する。

## 話題選定とOpenCodeの接続

ユーザー指定のVertex AIプロジェクトと`gemini-3.8-flash`を使う。話題選定は保存済みASRから1回だけ呼び、時間・使用量を記録する。認証エラーやモデル未提供では停止し、別モデルへ自動変更しない。初回の鍵なし認証設定と、通常制作から独立したOpenCodeハーネスは[VERTEX_GEMINI.md](VERTEX_GEMINI.md)を参照。

## 字幕の編集方針（2026-10-26）

横長字幕は画面幅を広く使い、通常2行・必要時3行、同じ話者の短文をまとめて切替を減らす。話者色、意味を保つケバ取り、3.5 Flashによる根拠付き固有名詞調査を使う音声編集経路は[GEMINI_AUDIO_REVIEW.md](GEMINI_AUDIO_REVIEW.md)を参照。テキストだけの候補計画から話者を推定しない。既存の納品動画は自動で作り直さない。
