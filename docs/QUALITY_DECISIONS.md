# 品質の決定事項

現在の規則と実装上の限界をまとめる。過去の実験や取り消し済みの案は [記録一覧](archive/README.md) を参照する。数値は既存の決定を維持し、過去の合格記録を現在の全条件への適合と読み替えない。

## 1. 文字起こし

- 既定モデルは `mobiuslabsgmbh/faster-whisper-large-v3-turbo`。固定リビジョンは `signals.PINNED_REVISIONS`、設定は `Settings` と各config例を正とする。
- Colabの既定候補はASRがT4の2形状、描画がCPUの2形状。空き不足だけを理由にL4や描画用GPUへ自動で上げない。
- URL経路は既定2分割、各部分は逐次認識。結合済みASRを後段へ渡し、プレビュー・描画で認識をやり直さない。[分割・結合・終了条件](ASR_SPLIT.md)を参照。
- `threads=0` は自動。横用configの `2` は明示値。描画用 `encode_threads=0` とは別の設定。
- `asr_batch_size=0` が既定。GPUの通常運用は逐次処理を使う。コードは明示された非ゼロ値を実行するため、「GPUでは無視される」とは扱わない。バッチ処理は話題境界を変え得るため、認識速度だけを理由に既定へ変更しない。
- 単語時刻と元のASRを保持する。用語表記や反復の整理は字幕生成時に行う。認識精度・固有名詞は機械の確からしさだけで合格としない。

## 2. 字幕の区切り・改行

- BudouXの文節とfugashi/UniDicの語境界を使い、単語内や連続カタカナの分割を避ける。2行では文節を優先して幅をそろえ、Pillowの実フォント幅で画面内に収める。
- 字幕は最大2行。結合時の4秒制限を維持する。読む時間を確保するための表示延長で4秒を超えた場合も警告として記録する。
- 最短表示の警告値は0.5秒、無音がある場合の延長目標は1秒。横の読み速度は7字/秒、縦の延長目標は10字/秒。警告値は `quality.reading_limit` と設定を参照する。
- 表示延長は後ろの空きを使い、横字幕では前の空きも最大0.5秒使う。他の字幕と重ねず、音声は変更しない。ASSとSRTの本文・時刻を一致させる。
- NFC正規化、結合文字の保持、用語表記、全角の疑問符・感嘆符と後続スペースを字幕側で処理する。元のASRを字幕表記で上書きしない。
- 書き出しはpysubs2へ統一。幅に収まらない長い語や比例分割の時刻は人による確認が必要。

## 3. 文末判定

文末はfugashi/UniDicの品詞と前後の語で判定する。後続の助詞・助動詞がある場合は続きとして扱う。正規表現による旧版の丁寧語判定を再導入しない。無音・文末・語境界を併用し、本文の削除や単語時刻の移動で警告を減らさない。

## 4. 横画面（16:9）の規則

- 主な納品対象は同じ配信の異なる話題3〜5本、1920×1080、尺20〜180秒。横用configを明示する。CLI全体の既定aspectは縦なので、configなしで横になるとは扱わない。
- 読み速度の目標・警告は7字/秒。基本の行長は全角13字相当・最大2行。チャット欄では `Settings.caption_line_chars()` の画面幅・フォントに応じた値を使う。
- 字幕は下中央。動かない画面情報の上だけへ持ち上げ、上端へ移動しない。持ち上げと承認値 `caption_floor` の上限は高さの0.32。承認値は入口とworkerで共通の `review.py` により検査する。
- チャット幅・cropは設定と承認値を使い、判定結果をrender receiptに保存する。固定画面との重なりは警告。動くワイプ、ズーム、追加画像との重なりは機械検査だけで保証しない。
- 元のNetflixガイドとClipForgeの7字/秒基準は同一ではない。機械警告が減っても、読みやすさが改善した証明にはしない。

## 5. 品質検査

`quality.json` は失敗・警告・測定値を分ける。既定 `quality_gate=strict` が停止するのは失敗がある場合。警告0件・内容承認・納品条件の全達成とは別。

| 項目 | 現行の扱い |
| --- | --- |
| ASS/SRT不一致、字幕重複、3行以上、画面超過、文字欠け、出典欠落、復号失敗 | 失敗。strictで確定を停止 |
| 音量を測定できない、音声が48kHzでない | 失敗 |
| 音量が−16±1 LUFS外、真ピークが−1 dBTP超、無音 | 警告。strictだけでは止まらない |
| 読み速度、短すぎる表示、4秒超、語割れ推定、固定画面との重なり、和文スタイル | 警告。数値と内容を確認 |

音声処理の現行値は `media.LOUDNESS`（I=−16、TP=−2.0）、後段リミッターは `media.PEAK_LIMIT`（約−3 dBFS）。完成AACの真ピークを測る。旧記録のTP=−2.5・192kHzリミッターは現行コードの説明として使わない。

納品は、機械検査に加えて必要な数値目標と内容を確認する。[受入条件](LANDSCAPE_PLAN.md)を参照。真ピーク−0.8 dBTPを含む過去の実行は、処理完走の記録であり、−1 dBTP以下の達成記録ではない。修正後の実動画による再確認は別に記録する。

## 6. Gemini のモデル

URL音声先行経路はGeminiを使わない。ローカル動画の自動選定だけ、明示したモデルへ候補映像・音声・該当ASRを送る。config例のモデル識別子は設定値であり、現在の提供継続・無料枠・割当を保証しない。

生成は1回。拒否・不正応答で別モデルへ切り替えない。Google用スキーマとPydanticの両方で応答を検査する。アップロード済みファイルの削除を試み、成否を記録する。手動選定とcutでは生成しない。

## 7. 完成と追加改善の境界

機械処理の完了、品質数値の達成、人による内容確認、公開を分ける。話題の完結性・認識誤り・意味的な重複は人が確認する。固定の時間やCUは過去の測定値として扱い、入力や割当が違う実行の保証にしない。

2分割と連続認識の表記差やGPU実行ごとの揺れは既知の限界。同じSHAでの比較、モデル探索、字幕の細かな閾値比較、キャッシュ構築は、具体的な問題を調べる場合だけ行う。重い依存や新しい生成経路を通常の整理作業へ追加しない。

過去の採否の理由・計測は [旧決定記録](archive/QUALITY_DECISIONS_2026-10-23.md) と [品質計測記録](archive/QUALITY_REVIEW.md) に残す。現在の未確認事項は [受入条件](LANDSCAPE_PLAN.md#未決事項未確認) を参照する。
