# 品質の決定事項

ClipForge の文字起こし、字幕の区切り・改行、文末判定、横画面の規則、品質検査について、現在有効な決定だけをまとめます。

- 数値と日付は計測時の記録のとおりです。推測で補った値はありません。
- 後の決定で覆された内容は、末尾の「取り消し」にだけ書きます。
- 発話の本文と秘密情報は書きません。

## 1. 文字起こし

- 文字起こしは NVIDIA Parakeet（`nvidia/parakeet-tdt_ctc-0.6b-ja`、NeMo 3.0.0）だけを使います。Whisper は 2026-10-24 に削除しました。手順は [ASR.md](ASR.md)。
  - 根拠：2026-10-23 の比較試験で、同じ区間の文字起こしが Parakeet で通り、字幕にもそのまま使えたため。話題分けの質は実配信で確認が必要です（下の「未確認」）。
- 1つの文字起こしを、話題分けと字幕の両方に使います。区間ごとの起こし直しはしません。
- 保存済みの文字起こしは、分析が記録した鍵で読みます。後の段階で認識をやり直しません。
- 用語の綴り辞書を、`ai`・`agi`・`asi` から `chatgpt`・`openai`・`ollama`・`gpu`・`cpu`・`api`・`llm`・`youtube`・`gemini`・`claude` などへ広げます。`Kick` は英語の一般語と紛れるため入れません。
- 2語の用語（`LM Studio`・`Hugging Face`・`OpenAI`・`ChatGPT` など）は、隣り合うトークンが完全に一致したときだけ1つにまとめます。開始は最初の語、終了は最後の語の時刻を使います。句読点が付いた語は一致させません。
- 固有名詞の誤認識は残ります。固有名詞の確認は人が行い、直す箇所は承認ファイルの `caption_edits` で指定します。

## 2. 字幕の区切り・改行

- 語の途中で行や字幕を切りません（熟語・送り仮名を割らない）。
  - 根拠：語の途中で切れる字幕の境界は 16 件から 0 件（15分の実動画）。
- 行の途中の改行候補は、次の規則です。
  - 助詞（は・が・を・に・で・と・の・へ・も、かな・カタカナ・英数字の後の や・か・ね・よ を含む）の前を候補にする。漢字の後は主な助詞だけを候補にする。
  - カタカナ・英数字・漢字の変わり目を候補にする。
  - 漢字どうし、カタカナどうし、英数字どうしは改行しない。
  - 閉じ括弧・三点リーダの後を候補にする（行頭には置かない）。
  - 根拠（15分の実動画 `e2e-final4`、旧 `b6a889a` → 新）：字幕数 59 → 56、行の途中の改行（漢字・カタカナ・英数字の内部）0 → 0、字幕の切れ目（かな同士）9 → 14、字幕の切れ目（その他）48 → 40。
- 2行の字幕は、上下の行の幅の差が最も小さい境界を選びます。ただし文節の境界を優先し、行頭に助詞を置きません。
  - 根拠（15分の実動画 `e2e-final4`）：2行の長さの差（平均）0.24 → 0.22、短い2行目 1 → 1、画面超過 0、語の途中の改行 0、行頭が助詞の2行目 5 → 5。
- 字幕の左右の余白は 25 px です（高さ720基準。1920の縦では片側 67 px ≈ 6%）。
  - 根拠（15分の実動画、1080×1920）：1秒未満の字幕 8 → 1（60件中）、かな同士の境界 14 → 9（58件中）、字幕の中央値 1.58 秒 → 1.98 秒。
- 字幕の読み速度の目安は 1秒あたり10文字です。次の字幕までの無音があれば表示を延ばします。15文字を超えて残る字幕は警告です（横画面の基準は後述の4を参照）。
  - 根拠：15分の実動画の字幕の読み速度の中央値は 7.6・7.2 字/秒。clip-001 の末尾に 15.5 字/秒の字幕が1件（警告）。
- 1秒未満・4秒超の字幕は警告にします（1秒未満は断片のため）。
  - 根拠：既存の出力2本に検査を当てたところ、偽陽性はなく、1秒未満の警告だけが出た。
- 2行・4秒の上限は緩めません。隣と結合できない1秒未満の字幕は、仕様上の結果として残します。
  - 根拠：15分の実動画で 1秒未満 2 件（56件中）。どちらも表示を延ばせる無音がない。最新版（2行の長さ揃えを採用）では 1 件（57件中）。
- 数字・英数字・URL（例：`GPT-4o`、`v1.2`、`https://...`）は、行の途中で分けません。
- 結合文字は基字から切り離さず、文字列は Unicode の NFC で正規化してから組みます。
- 字幕の幅は Pillow の `ImageFont.getlength` で測ります。`getbbox` への変更はしません。
- 文節の境界には `budoux`（`captions.parser()`、0.10.0）を使います。字幕の書き出しには `pysubs2` を使います。どちらも既に使用中です。

## 3. 文末判定

- 文末は、形態素解析（`fugashi` 1.5.2、`unidic-lite` 1.0.8）の品詞で判定します。
  - 文末とみなすもの：です・ます（どの活用形でも）、だ（終止形）、た（終止形で、直前が です・ます・だ）、終助詞（ね・よ・か・な など）。
  - 後に助詞・助動詞が続く場合は、文が続くとみなして区切りません。
  - その字幕が1秒以上続いていれば、文末で区切ります。
  - 根拠（15分の実動画 `e2e-final4`、丁寧語の正規表現版 `858d303` → 形態素版）：字幕数 57 → 57、1秒未満 2 → 1、字幕の先頭が終助詞で始まる 6 → 1、先頭が助詞・助動詞の割合 30%（17/57）→ 19%（11/57）。末尾が文末になる割合は両方 33%（19/57）で、この指標は改善を示しません。
- 文字起こしには句読点がほとんど出ないため、字幕の区切りは無音と語の境界に加えて、文末の判定にも頼ります。
  - 根拠：句読点で終わる語は 4194語中 2 語。
- 「てる」「じゃん」は判定に入れていません。「だった」「ちゃった」は後に接続詞などが続く場合に判定されますが、該当が1本にないため効果は未検証です。
- 正規表現による丁寧語の判定は取り除きました（「取り消し」を参照）。

## 4. 横画面（16:9）の規則

- 規則の基準は、Netflix の日本語字幕ガイド（標準字幕）です。1行は全角13字以内・最大2行、読み速度は 7字/秒を基準とします（2026-10-22、利用者の決定。ガイドの標準は 4字/秒）（[Japanese Timed Text Style Guide v4.0](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215767517-Japanese-Timed-Text-Style-Guide-v4-0)）。
- 横画面の出力は 1920×1080 で、`--config config.landscape.example.json` で指定します。
  - 根拠（16:9、保存済みの文字起こしのサンプル）：両クリップとも品質ゲートを通過。−16.0 LUFS、真ピーク −1.4 dBTP、画面はみ出し 0、語の途中の改行 0、文頭の句読点 0、文頭の終助詞 0。1行の最長は 14字（一部が半角のため。ガイドは半角を 0.5字として数える）。
- 横字幕の表示延長目標と警告基準は、**7字/秒**です（2026-10-22、利用者の判断。Netflix v4.0 の SDH 上限 II.18 に相当。一般字幕は I.18 の4字/秒）。比較用に 4・7・10字/秒の超過件数を記録します。7字/秒への変更で警告が減っても、読みやすさが改善したとは呼びません。
  - 根拠：サンプルの読み速度の中央値は 7.0字/秒。4字/秒超は 45/46 件、7字/秒は 23/46、8字/秒は 15/46、10字/秒は 2/46。
- **決定**：横画面の読み速度の基準は 7字/秒（2026-10-22、利用者の判断）。1行の上限は 13字のまま（SDH の16字には広げていない）。
  - 根拠：標準の4字/秒は、話し言葉の字幕ではほぼ常に警告になります（元の記録の見立て）。
- 最小表示：0.5秒（2026-10-22、利用者の決定）。0.5秒未満の字幕は警告します。無音があれば、字幕は1秒まで延ばします（開始時刻は変えず、次の字幕の開始と動画の終わりを超えません）。0.5秒と1秒の値は `caption_breaks.py` の `MIN_DISPLAY_SECONDS`（警告）と `MIN_CAPTION_SECONDS`（延長・文末分割）で別々に定めます。
- 横画面は、話題の割り振りと候補の確認を先に行い、採用区間だけ高画質で取得します（音声取得 → 話題割り振り → 候補映像の確認 → 採用区間の高画質取得 → 横動画生成）。全編の高画質映像や場面検出へ先に進みません。
  - 根拠：段階の順序、音声取得時に ASR を呼ばないこと、レビュー前に高画質を取得しないことを合成入力で検証。
- 縦（ショート）は今回の対象外です。
- 品質ゲートの strict 通過は、警告0件や内容の承認を意味しません。

### 字幕の位置（2026-10-23）

- **規則**：字幕は下中央に置くことを基本とします。画面の下端に接して動かない細部（HUD・ホットバー・ハート・ワイプの背景・重ね表示）の帯があるときだけ、その帯の上端の少し上（1.5% の余裕）へ持ち上げます。上限は映像の高さの 32% です。字幕を画面の上端へ移すことはしません。2秒未満の間隔で隣り合う字幕は、高い方にそろえます（隣の字幕だけ）。
  - 適用：16:9 の横画面のすべて（チャット欄 fill、チャット欄なしの fit・blur）。縦型は対象外です。`caption_lift`（既定 true）で止められます。`panels` 配置は帯を判定しないため、基準の下余白のままにします（`render.json` の `layout.reason` が `panels`）。
  - 基準の余白：チャット欄なしは 1080 p で 130 px（字幕は 52 px・1行13字）。チャット欄 fill は 130 px（字幕は 72 px・2行・1行18字）。
- **承認ファイルの `caption_floor`**（任意、0〜0.32、映像の高さに対する下余白の最小値）：指定したクリップの各字幕の余白を、最低この高さにします（`max(持ち上げ, caption_floor)`）。自動判定が拾えないワイプの対策に使います。投入前（`tools/submit_audio_stage.py`）と worker（`audio_first.py`）で範囲を検証し、範囲外は拒否します。`render.json` の `layout.floor` と描画の鍵に記録します。
- **判定**：字幕の前後3秒（最低5フレーム、最大64フレーム）の映像の勾配について、画素ごとの時間方向の中央値をとります。動く対象（ゲームの映像）は消え、動かない細部だけが残ります。行ごとの平均が窓の行の中央値の 1.6 倍を超える行を混んだ行とし、底辺に接し、底辺から高さの40%までに収まる混んだ帯の上端より上へ持ち上げます。窓は全体、左右の半分のそれぞれで判定し、どれか一つで帯があれば採ります。チャット欄の暗い帯（overlay の列）は判定から除きます。
  - 根拠：合成映像（testsrc2 1920×1080、下部の静止した帯）で、帯の上に字幕が来ることを1フレームで目視確認（2026-10-23。作業用の PNG はリポジトリに含めない）。
- **品質検査**：描画時の帯（`render.json` の `layout.static`）と字幕の箱（余白と行数×フォントの高さ、幅は中央揃えの推定）が重なれば、警告「N caption(s) overlap static screen elements」を出します。合否には影響しません。映像は再解析しません。
- **採用理由**：利用者の評価として、字幕を上端へ移す形は不格好で、下に帯を作る形も不格好とされました。固定画面には字幕を重ねないことを求めています。その要求を、映像の上の細部を判定して字幕を持ち上げる方法で満たします。
- **既知の限界**：
  - 中身が動くワイプは、動かない枠などが見えるときだけ拾えます。拾えなければ `caption_floor` で指定します。
  - 元映像が 16:9 でない場合、縦の切り抜きは判定に入れません（幅の切り抜きだけ見ます）。
  - 警告の横幅は推定です。実際の字形より広く見積もることがあります（1行 52 px で 11 字は 572 px と推定）。

## 5. 品質検査

### 日本語字幕の機械警告（Netflix v4.0）

- 次の4点を警告に追加します。合否（`failures`）には影響しません。
  - 句点「。」・読点「、」の使用（I.17：使用しない）。該当字幕数のみ記録します。
  - 半角 `?`・`!` の使用（I.17：全角を使う）。
  - 疑問符・感嘆符の後に文が続く際の全角スペース欠落（I.17）。記号の連続、行末、閉じ括弧直前は対象外です。
  - 横画面で1行13全角字を超過（I.5）。半角は0.5字として数え、既存の画素幅検査とは独立に判定します。
- 句読点以外は件数と最初の例（字幕文字列を最大10文字）を記録します。句読点・半角記号・スペースは字幕単位、字数超過は行単位で数えます。

### 品質ゲートと音量

- `quality.json` に、字幕の重なり、フォントにない文字、出典・ライセンスの欠落、EBU R128 の統合ラウドネス（−16 LUFS ±1 LU）、真ピーク（−1 dBTP 以下）を記録します。既定の `quality_gate=strict` では、失敗のあるクリップを確定しません。
  - 根拠：最終確認（既定値、コミット `023af86`）で両クリップが通過。−16.0 LUFS、真ピーク −1.4 dBTP。
- 音量の目標は −16 LUFS、loudnorm の真ピーク目標は −2.0 dBTP です。その後段で、サンプルピークを −3 dBFS（`alimiter`、`PEAK_LIMIT = 0.7079`）に抑えます。2026-10-23 の通し実行で、−2 dBFS では1本が鋭い音1か所のAAC圧縮後のはみ出し（+1.15 dB）により −0.8 dBTP になりました。3本で比べると、−3 dBFS で真ピークが 0.5〜0.9 dB 下がり、音量の変化は 0.2 LU 以内でした。
  - 理由：AAC の符号化で真ピークが約 +0.6 dB 上振れします。実配信の3本は AAC 後に −0.9 dBTP で、品質ゲート（−1 dBTP 以下）の余裕がありませんでした。ノイズの急な立ち上がりを含む合成音では、loudnorm 直後 −1.4 dBTP が AAC 後 0.0 dBTP になりました（リミッター追加前）。
- 完成ファイルは最後まで復号して、エラーがないことを確認します。失敗は strict で停止します。出力の音声は 48 kHz であることを確認します。
- ASS と SRT は、時刻と本文が一致することを確認します。3行以上の字幕は失敗です。

### 元動画と出力先

- 送信前と出力確定前に、元動画の SHA-256 と照合します。
- 出力ディレクトリとその親のシンボリックリンクは拒否します。空の入力は、処理の開始前にサイズで拒否します。
- 壊れたキャッシュ記録は完了結果として採用せず、その段階を再計算します。

### 映像と解像度

- 縦の既定出力は 1080×1920 です（720 と 1080 は選択可能）。字幕の余白と縁は高さに比例させます（720 px では従来と同じ値）。
  - 根拠（15分の実動画、既定値、コミット `38815a4`）：字幕の境界で語が割れた件数 0。品質ゲートは両クリップとも通過（−16.0 LUFS、真ピーク −1.4 dBTP）。
- 符号化は `slow`・CRF 18 です。
  - 根拠：40秒の切り抜きで、PSNR が `veryfast`・CRF 20 より約 3.9 dB 高く、時間はほぼ同じ。
- 描画・フィルタは `encode_threads=0`（実行環境で利用できる全コア）が既定です。ASRの `threads` とは独立し、描画用スレッド数をASR再利用キーに含めません。
  - 根拠：Colab CPU High-RAMの8コア環境で、x264が2スレッドに制限され、1クリップ120〜307秒を要したため。
- 音声先行経路の採用区間の高画質取得はremux（再符号化なし）です。字幕焼き込みを含む最終描画の再エンコードとは区別します。
- レイアウトは `blur`（ぼかし背景）です。
  - 根拠：ぼかし背景、見出し、2行字幕、出典表示、進捗バーを目視で確認（コミット `023af86`）。

### 自動検査と公開

- 自動検査の合格条件は、Python 3.11 / 3.12 と、単体テストのカバレッジ 90% 以上です。通常の CI は外部の LLM を呼びません。
- 人が確認する前に自動公開しません。合成動画での検査は、配信の面白さや日本語の認識精度を保証しません。
- 数値の共有用の要約には、詳細な警告の発話例と素材のパスを含めません。

## 7. 採用しなかった案とその理由

- **拡大方式の変更**（lanczos・軽い unsharp）：bicubic と差がほとんど見えなかったため、bicubic を維持します。元映像の解像度と圧縮が上限です。
- **文末の句読点による字幕の区切り**：字幕の統計は 1 件も変わらず、効果が測れないため取り除きました。
  - 根拠：句読点で終わる語は 4194語中 2 語。
- **0.3秒以上のポーズを文末の必須条件にする版**：丁寧語の区切りまで減りました（末尾の割合 4%）。
- **助動詞の終止形を広く取る版**：「〜たい」「〜ない」で誤って区切りました。
- **無音0.35秒での区切り**：字幕が 57 から 59 に増え、1秒未満の字幕が増え、長さの差も悪化（0.29）しました。
- **無音0.5秒・0.6秒での区切り**：元の記録は「字幕は変わらない」としています。表では行頭が助詞の2行目が 5 から 11 に増えます。採用の記載はありません。
- **2行の長さの揃えを文節の境界に限らない版**：文節の内側で割り、行頭が助詞の2行目が 5 から 14 に増えました（長さの差は 0.18）。
- **字幕の結合上限と最短表示の組み合わせの変更**（無音 0.7・1.0秒、最短表示 0.8・1.0秒）：効果がありませんでした。結合は2行・4秒の上限で止まるためです。既定値は変更しません。
- **2行・4秒の上限を緩めて1秒未満の字幕を結合する案**：読みやすさを下げるため採りません。
- **字幕を画面上端へ移す**：利用者の評価で不格好とされたため採用しません。字幕の位置は下中央を基本とし、動かない細部の上へだけ持ち上げます。
- **映像を縮めて下に字幕帯を作る**：利用者の評価で不格好とされたため採用しません。字幕のための帯を作るには映像を縮める必要があり、映像の大きさが変わります。
- **固定字数での折り返し**（14文字で折る）：実際のレイアウトに合いません。14文字では 59 字幕のうち 22 件が画面幅を超え、10文字でも 3 件超えました。画素幅で折り返す現行方式は超過 0 件です。
- **`getbbox` による字幕幅の計測**：利点が小さいため変更しません。
