# 確認待ち制作経路の点検（2026-10-28）

コードとオフラインテストを対象に確認した記録。実配信・GitHub Actions・Colab・非公開Release・Vertexへの投入や接続確認は行っていない。実素材の字幕精度、所要時間、ブラウザー上の操作、実際の認証・回収は未確認。

| 工程 | 確認した経路 | 制限 |
|---|---|---|
| 対象の指定 | 通常CLIはURL・本数・設定・40桁コードSHAを明示する。投入前に依頼IDを保存する | 本数は目安。Actionsの定義は `main` を使い、コードは指定SHAを使う |
| 話題・文字起こし・清書 | 既存の3.8話題選定、3.5 Transcribe、3.8清書を使用。清書が実際に受理した元IDを確認用に記録する | 新ルールの効果や認識精度は実素材で未検証。モデルの追加査読はしない |
| 確認用パッケージ | 話題別動画、字幕と確認箇所、選定・字幕データを非公開ZIPにまとめる。近接する確認箇所をまとめ、元IDの対応不明と未使用の元発言も表示する | 固有名詞やすべての誤りを自動検出できるわけではない。ファイルサイズ上限は1900 MiB |
| 利用者の確認 | 語の変更が少ない順、話者・変更候補、参考用の抜き取り、各動画の境界への移動を用意する | 機械的な候補は人の視聴ではない。利用者の判断に合わせて確認し、実際の確認範囲を記録する |
| 描画の承認 | 自動描画を無効化。CLIは承認と確認状態を要求し、ZIP・選定・字幕のハッシュを照合する | 明示フラグは人が実際に視聴した証明ではない。ワークフロー定義を `main` に反映するまでは新経路を使えない |
| 修正 | 指定パッチを親版から作成し、確認パッケージの親データのハッシュと照合してから非公開に別版を保存する | 修正内容と承認は利用者の指示が必要。モデルは再呼び出ししない |
| 完成物の回収 | 転送記録とZIPをRESTで取得し、Release assetのサイズ、記録されたファイルとハッシュを照合する | REST・認証・実Releaseでの動作は未確認。401・403等を別アカウントや別経路で回避しない |
| 納品 | 指定時だけ既存Drive経路へ進む | 配信者の許可、宛先と納品前確認は別途必要。実際のDrive転送は未検証 |

確認動画と完成版の素材は同じURLから別々に取得する。URLの中身が確認後に差し替わった場合の同一性までは検証できない。確認動画には字幕を焼き込まないため、実際の字幕の位置・同期・無音時の表示は描画後に見る必要がある。

ルールブック内の「言い淀みを残す」規則と例の不一致、聞き取れない語の扱い、未実装の黄色強調の記述を修正した。共通ルールのハッシュが変わるため、新ルールのモデル要求では旧ハッシュの応答を再利用しない。以前の保存済み成果物は変更しない。
