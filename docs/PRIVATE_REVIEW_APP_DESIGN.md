# 非公開の動画確認・修正アプリの設計

## 目標と現在の状態

スマートフォンから認証して開き、字幕を重ねた動画を再生し、字幕をタップして修正する。修正をサーバーに保存し、対象・設定・コードを確認して明示的に承認した後、既存の render-only 経路で描画する。非公開の公開サービスはまだ実装・公開されていない。

## ローカル試作

`python -m clipforge.review_local_server PACKAGE --patch-output PRIVATE_PATCH` は、同じコンピューターの `127.0.0.1` だけで確認画面と ZIP 内の動画を提供し、修正をサーバー側のファイルへ保存する試作。別端末からは開けない。ローカルの別ユーザーやプロセスに対する認証はなく、リバースプロキシやトンネルで公開しない。複数タブでの同時編集は後の保存が上書きする。動画のプレビューは既存の簡易表示で、ASS 表示と描画起動はない。停止すると画面には接続できないが、保存済みのパッチは残る。パッチ出力先はリポジトリ外の非公開ディレクトリを指定する。

## 境界

- HTML、字幕、動画、修正データ、描画状況はすべて認証・認可された本人にだけ返す。公開 Pages、公開 Artifact、公開 Gist、公開 issue に字幕や動画を置かない。認証情報を HTML、動画 URL、ログ、ブラウザーへ埋め込まない。
- 動画は既存の確認用映像を非公開ストレージから同一オリジンの認証付き経路で配信する。サイズの大きい動画を HTML に埋め込まない。HTTP Range と部分応答を扱い、途中再生とシークを実機で確認する。Drive や Release の URL が `<video>` で再生できると仮定しない。
- サーバー上の確認対象は明示的に登録する。動画、選定、字幕、確認パッケージ、親編集 Release、保存済み Run/request と SHA-256 を対応づけ、利用者から任意の URL やリポジトリを受け付けない。
- UI は動画上の字幕をタップして本文・時刻を修正できるようにし、保存済みの変更を再表示する。変更が未保存・保存中・失敗・保存済みの区別を表示し、画面を閉じても変更が残るようにする。

## プレビューと字幕の対応

JASSUB などの libass による ASS 表示を候補とする。本番に使うフォント、画面サイズ、字幕生成設定を揃える。ただしブラウザーと FFmpeg の完全一致を保証しない。対象端末で描画とフォントの読み込みを確認し、使えない場合は表示が簡易版であることを示す。

本番 ASS のイベントは元の字幕 segment と一対一ではない。`captions.py` は複数発話の結合、改行、表示時間の調整を行うため、画面に表示されたイベントと元 segment の対応を明示的に作る。タップ時に複数 segment が対応する場合は、対応する候補を利用者が選べるようにする。対応不明な字幕を別の segment に自動で割り当てない。編集時は ASS を更新し、編集内容が保持されていることを確認する。

## 保存と描画

- 保存は認証済み POST とし、入力の形式・文字・時刻・対象の範囲をサーバーで検証する。CSRF 対策、容量制限、複数端末の版の衝突検出を行う。認証付き保存は描画承認と別にする。
- 既存の修正パッチ形式と `input_fingerprint` を使い、親の選定と字幕を照合する。追加字幕の話者は推測しない。元データとモデル応答は書き換えない。
- 描画ボタンの直前に対象、変更内容、元の編集 Release、画質・設定、使用する40桁コード SHA を提示する。承認された内容だけを固定し、既存の `--review-approved`、`--review-state`、`--editorial-release`、`--revision-file` を用いる。必要なら前回の完成 Run/request で `--reuse-render` を使う。
- 同じ承認による同時投入を防ぎ、投入前に `dispatching_or_unknown` を永続化する。通信エラーや応答不明の場合は自動再投入せず、状態を調べて同じ Run を監視・回収する。
- 承認時にこの制作の URL・本数・設定・コード SHA が明示されていなければ投入しない。モデルの追加要求は行わない。

## 実装前に解決が必要な点

1. 本人限定で使える HTTPS ホスティング、永続ストレージ、GitHub の最小権限サーバー認証の利用可能性を確認する。ブラウザーに権限を渡さない。
2. 非公開の確認動画をサービスへ安全に登録し、シークできる配信経路を用意する。所有者・保存場所・アクセス権限を確認する。
3. 既存の `production-state.json` と確認パッケージの照合を、サーバー側で使える形にする。確認後の修正の適用先と内容を固定する。
4. ASS イベントと segment の対応、フォント、本番設定を検証する。スマートフォンのブラウザーで動画再生・タップ・保存・再開を実測する。
5. 配信と保存が正常でも、描画投入・失敗時の回収を検証できるまでは一連の経路を完成と報告しない。
