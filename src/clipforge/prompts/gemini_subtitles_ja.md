# Gemini 3.8 Flash: 文字起こしの清書（採用話題ごと）

共通の「ClipForge 編集ルールブック」を適用します。入力は採用話題の音声と、その区間をGemini 3.5 Transcribeで文字起こしした文章・各発話の元の時刻・話者ラベルです。音声を参照しながら元の情報・順序・意味・口調を保ち、明らかな誤字・脱字・誤認識だけを直します。話者は判定せず、効果音も出しません。全文を新たに書き起こしません。

- 採用話題ごとに1回、前後の文脈を見て処理します。要約、同義語への言い換え、情報圧縮、一文への強制結合はしません。
- 字幕本文には句読点（、。）を使わず、言葉の間は全角スペースで区切ります（目安）。「？」「！」は残してかまいません。
- 1行は13〜18字を目安に、意味の区切り（文節）で分けます。15字刻みの機械的な分割はしません。目安に届かなくても、文節を崩さないことを優先します。
- 言い淀み・吃り・相槌・反復・言い直し前の断片は削除しません。驚き・返答・否定・ためらい・強調も残し、曖昧なら元の表現を保持します。
- 小さい声や短い相槌も聞こえた発話なら残します。元IDの内容を丸ごと省かず、発話か不確かな場合も元の文字を残します。
- 音声から確かめられない語は作らず、入力にないIDの時刻を推測して新しい字幕を作りません。聞き取れない箇所は入力の表記をそのまま残します。
- 否定・数字・単位・条件・因果・対象・推測・伝聞・未確認の度合い・語尾・方言・結論・オチを保持します。話されていない主語・接続語・理由・結論を足しません。
- 誤字・脱字・誤認識は、音声と入力から訂正先が明確な場合だけ直します。固有名詞や数字を推測しません。不確かな箇所は入力の表記をそのまま残します。
- 語の置き換えは、音声を聞いて明らかに別の語だと確かめられる場合だけにします。音が似ていない語への置き換え、文の追加、言い換え、「。」を「？」に変えることはしません。迷ったら入力の表記を残します。
- `source_ids`には各字幕が使用する連続した元IDを順に入れます。発話順を変えず、長い無音をまたぐIDをまとめません。各元IDに内容を残し、相槌や反復も消しません。
- 元の時刻はコードがIDから引き継ぎます。時刻を作り直したり、次の発言を先に出したりしません。モデルの推測秒数で元IDを分割しません。感情はneutralにします。
- 話者はTranscribeの話者ラベルをそのまま使い、判定しません。`speaker_assignments`は空配列で返します。効果音は出さないので`sound_effects`も空配列で返します。
- 同じ応答の `review_hints` に、人が優先して確認すると役立つ箇所だけをまとめます。声の重なりや複数人の切替が曖昧な箇所、聞き取りや語の修正が不確かな箇所を、対象の元 `source_ids`、種類、短い理由で示します。候補がなければ空配列です。話者の名前や人物の同一性を推定せず、時刻は元IDからコードが求めます。候補は字幕の変更指示や確認済みの証明ではありません。
- 話題の音声と文字起こしを冒頭から末尾まで照らし、発言の欠落・誤字脱字・誤認識、別の声が同じラベルに混じる可能性、同時発話や短い相槌、発話と字幕時刻の大きなずれに注意します。音声で訂正先が明確な語だけ字幕を直し、判断に迷う語や話者・時刻の問題は元ID付きの確認候補にします。推測でラベルや時刻を変更せず、候補数の目標や機械的な全行列挙は設けません。

指定されたJSONだけを返します。例えば文字起こしのID 1が「えっと、昨日あそこ行ったんだけど」、ID 2が「雨すごくてさ、結局入れなかったんだよね」で、同じ話者ラベルの発話の場合：

```json
{
  "audio_access": "heard",
  "segments": [
    {"source_ids": [1, 2], "text": "えっと　昨日あそこ行ったんだけど　雨すごくてさ　結局入れなかったんだよね"}
  ],
  "review_hints": [],
  "speaker_assignments": [],
  "sound_effects": []
}
```

音声が利用できない場合はaudio_accessをunavailableにします。コードは音声なしの清書を成功と扱わず停止します。字幕の文字色・表示位置・フォント・行組みは描画側が決めます。
