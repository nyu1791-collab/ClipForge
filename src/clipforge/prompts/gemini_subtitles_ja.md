# Gemini 3.5 Flash: GPU文字起こしからの整文字幕

共通の「ClipForge 編集ルールブック」を適用します。入力は採用話題の音声と、その区間をGPUで文字起こしした文章・各発話の元の時刻です。音声を参照しながら元の情報・順序・意味・口調を保って整文し、声に基づき匿名の話者IDを付けます。全文を新たに書き起こしません。

- 採用話題ごとに1回、前後の文脈を見て処理します。要約、同義語への言い換え、情報圧縮、一文への強制結合はしません。
- 無意味と明らかなフィラー・吃り・言い直し前の未完の断片だけ除きます。驚き・返答・否定・ためらい・強調や意味のある反復は残し、曖昧なら元の表現を保持します。
- 小さい声や短い相槌も聞こえた発話なら残します。音声を確認でき、発話や意味のある笑い声等ではなく明らかにASRが音を誤認しただけの元IDは、`text`を空文字、`omit_non_speech`をtrueにします。発話か不確かな場合や一部に発話が含まれる場合は消しません。
- 否定・数字・単位・条件・因果・対象・推測・伝聞・未確認の度合い・語尾・方言・結論・オチを保持します。話されていない主語・接続語・理由・結論を足しません。
- 誤字・脱字・誤認識は、音声と入力から訂正先が明確な場合だけ直します。固有名詞や数字を推測しません。不確かな箇所は入力の表記をそのまま残します。
- `source_ids`には各字幕が使用する連続した元IDを順に入れます。発話順を変えず、長い無音をまたぐIDをまとめません。明らかな無意味フィラーだけを省く場合は `text` を空文字にし、`omit_filler` をtrueにします。判断が曖昧なら消しません。
- 元のGPU時刻をコードがIDから引き継ぎます。時刻を作り直したり、次の発言を先に出したりしません。音声の声質と話し方に基づいてクリップ内の同じ声には同じspeaker_1〜speaker_6を使います。話者IDは出現順で、クリップをまたぐ同一性や実名を意味しません。発話が重なる、ひとつの元IDに複数の声がある、声が短く判別できない、確信度が0.8未満の場合はunknownとします。文脈だけで話者を決めず、異なる話者の発言を結合しません。モデルの推測秒数で元IDを分割しません。感情はneutralにします。
- 必要なら共通ルールの効果音3種類だけを同じ応答で返します。元発話の時刻に基づき、深刻な内容を茶化しません。不要なら`sound_effects=[]`です。

指定されたJSONだけを返します。例えばGPUのID 1が「えっと、昨日あそこ行ったんだけど」、ID 2が「雨すごくてさ、結局入れなかったんだよね」で、無意味な「えっと」だと明確な場合：

```json
{
  "audio_access": "heard",
  "segments": [
    {"source_ids": [1, 2], "text": "昨日あそこ行ったんだけど、雨すごくてさ、結局入れなかったんだよね", "omit_filler": false, "speaker_id": "speaker_1", "confidence": 0.9}
  ],
  "sound_effects": []
}
```

音声が利用できない場合はaudio_accessをunavailableにします。コードは音声なしの整文を成功と扱わず停止します。字幕の文字色・表示位置・フォント・行組みは描画側が決めます。
