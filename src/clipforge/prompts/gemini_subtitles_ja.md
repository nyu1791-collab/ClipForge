# Gemini 3.8 Flash: 採用区間の字幕本文

この工程は、すでに選ばれた話題の音声を字幕にする工程です。全編の話題選定やGPU文字起こしは行いません。

## 何を字幕にするか

- 先頭に添付された「字幕対象音声」だけを文字起こしします。その後に添付された「話者参照音声」は声の識別にだけ使い、その言葉や時刻を字幕へ混ぜません。
- 今回指定する対象時間帯の中で、聞こえる発言を順番どおり残します。冒頭の言葉、短い返答、相づち、笑いながらの発言も、意味があれば字幕にします。
- 要約、言い換え、書き言葉への変換、意味の圧縮、発言の補完・創作はしません。話し方、語尾、くだけた表現、方言は、明らかな聞き取り誤りを直す場合以外は保ちます。
- 省いてよいのは、意味のない間を埋めるだけの「えー」「えっと」「あのー」、息だけの声、単純な吃り、言い直す前の未完の断片です。「なんか」「その」「まあ」などは、意味やニュアンスを持つなら残します。
- 気づき・驚きの「ああ」、返答の「うん」「はい」、同意・否定・ためらい・笑いの要点は残します。意味のある「あー」と、間を埋めるだけの「あー」を区別してください。
- 発言を消すことで否定、数字、条件、理由、固有名詞、結論、オチが変わらないようにします。

## 表記と読みやすさ

- 明らかな誤認識は、対象音声と会話の前後関係に合う場合だけ直します。渡された話題名や用語候補は参考情報であり、音声と合わない表記を採用しません。確信がなければ聞こえた表記を保ち、聞き取れない箇所だけ「［聞き取り不明］」とします。
- 日本語として自然な句読点と空白を使い、話していない説明文・括弧書き・見出しを字幕本文へ足しません。
- 読みやすさは、正しい聞き取り・自然な句読点・意味のまとまりで作ります。難しい言葉を勝手に簡単な別の言葉へ置き換えたり、敬語へ直したりしません。
- ひとつのsegmentは、一息または自然な意味のまとまりにします。長い発話は助詞や文節など意味の切れ目で分けます。固定文字数で細切れにせず、複数の文をひとつの長いsegmentへ詰め込みません。
- 画面上の行数・文字の大きさ・字幕の高さ・色・改行位置は描画プログラムが決めます。字幕本文のために内容を削ったり、15文字ごとに機械的に分割したりしません。

## 時刻

- 時刻は、今回添付された「字幕対象音声」だけの先頭を0秒にします。話者参照音声、元配信全体、切り抜き前の時刻を足しません。
- 発話の最初の聞こえる語から表示を始め、最後の語が終わったところで表示を終えます。長い無音を発話区間へ含めず、次の話者の発言に前の字幕を残しません。
- 指定された対象時間帯を担当します。前後の短い文脈用音声が付く場合、その外側の発言は本文へ出しません。
- 音声にない単語時刻を作らず、各segmentのstart/endは秒数で返します。単語単位の時刻ではなく、発話まとまり単位の時刻です。

## 話者

- 話者IDは匿名の `speaker_1` から `speaker_6`、判別できない場合は `unknown` です。添付された話者参照音声と同じ声だと確信できる場合は既存IDを再利用します。
- 確信度が0.8未満、声が重なる、声の識別が曖昧な場合は `unknown` にします。笑い・叫び・感情による一時的な声の変化だけで別人にしません。
- 発言内容だけから人物名、属性、関係を推測しません。

## 出力

指定されたJSONだけを返します。説明、Markdown、前置きは付けません。

```json
{
  "audio_access": "heard",
  "complete": true,
  "segments": [
    {
      "start": 0.0,
      "end": 2.4,
      "text": "昨日の配信でさ",
      "speaker_id": "speaker_1",
      "confidence": 0.96
    }
  ]
}
```

## 表記の例

音声が「えーと、昨日行った店、よかったんですよ」なら、意味のない「えーと」だけを除いて「昨日行った店、よかったんですよ」とします。文章を短く言い換えません。

音声が「ああ、そういうことか。うん、分かった」なら、気づきと返答なので両方を残します。
