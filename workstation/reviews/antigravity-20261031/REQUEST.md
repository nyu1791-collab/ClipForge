# Antigravityへの意見照会文

作成: 2026-10-31 UTC。以下はそのまま貼り付けられる現状説明と依頼文。回答はまだ取得していない。

## 利用するモデルと依頼の範囲

利用者の指定は「アンチグラビティの4 アルゴン」「推論高」。Antigravityのモデル選択画面・公式モデル一覧で、表示名と実際のモデルID、Highの対応を照合してから使うこと。現在のクラウドではその対応が確認できていない。別のGeminiやGPTへ置き換えたり、Antigravityの契約枠とVertex APIの利用権限を同一視したりしない。

今回は、以下の公開コードの構成とPC移行方法に対する一度の意見照会。通常の動画制作へ査読工程を追加する依頼ではない。未視聴の動画・字幕品質について合格判定を出さない。秘密情報、私有音声、動画、OAuth、Cookie、APIキー、.env、モデル応答の実データは渡さない。

## 達成したいこと

明日届く予定のCore i7・メモリ16GB・有線LANのPCで、現在GitHub中心の制作を管理し、CapCut Proで必要な仕上げを行えるようにする。GPU、VRAM、Windowsの版、空きディスク、CapCutの具体的な版は未確認。処理速度やNVENCが使えることは保証できない。

外部の自動化リポジトリをそのまま一式入れるのではなく、既存アプリと整合する機能を採用した。使うアプリごとに仮想環境を分け、動画・DB・秘密はソースと別のデータフォルダへ置く。各アプリのモデル、認証経路、DB、実行環境を一つに混ぜない。

## 共通のPC用入口

`workstation/manage.py` はPython標準ライブラリだけで使う。

1. `doctor`: ツールと環境変数の存在を表示する。秘密の値は出さず、認証成功とは判定しない。
2. `setup`: 既定は計画。`--apply` で選んだアプリ自身の環境だけに導入する。
3. `workspace`: 9件のカタログから選択して取得。既存フォルダをreset・上書きせず、取得SHAを `workspace-lock.json` に記録する。
4. `package`: 完成した動画・SRT/ASS・カバーを新しい保存先へコピーし、相対パスのmanifestとSHA-256一覧を作る。元字幕の時刻・本文を変更しない。再エンコード、AI生成、SNS投稿はしない。
5. `relink`: CapCut等の複製JSONの明示的なパス項目だけを書き換える。本文・ID・時刻は維持し、素材自体は移動しない。CapCutの非公式形式なので実機で開けるかは未確認。
6. `postiz-draft`: 下書き用JSONの書き出し。CapCut Pro契約をSNSのAPI権限の代わりに扱わない。

Linuxの `.venv` やGitHub Actionsの一時OIDCトークンをWindowsへコピーしない。PC移行だけを理由に、完了動画や既存Runを再投入しない。

現行main由来のAGENTS.md、docs/QUICK_START.md、docs/PRODUCTION_AND_REVISION.md、共通の字幕ルールを優先する。今回のPCアダプターで以下は変更していない。

URL → 音声取得/再利用 → Gemini 3.8 Flash/MEDIUMで話題・見出し選定 → 採用音声の仮切り出し → 3.5 Flash/MINIMALで表記調査1回 → 3.5 Transcribeで採用部分だけの文字起こし・単語時刻・話者分離 → 3.5 Flash/MEDIUMで話題ごとに整文 → Colab/NVENCで通常360p描画 → 保存・回収 → 指定時だけ納品。

全文GPU ASRや全文の精密文字起こしを復活させない。字幕は要約・言い換え・固定率圧縮をしない。情報・否定・条件・発言順・方言を保ち、意味のない言い淀みと明らかな誤認識だけを整える。15文字ごとの細分化をしない。匿名話者IDを推測で実名に結び付けない。制作全体に追加のモデル査読・品質ゲート・再描画を挿入しない。

以前の「制作データも公開へ統合する」作業は、未コミット変更をstashと非公開の控えに保存したまま。このPC対応で実行・公開・削除したことにしない。

## 今回こちらで見つけて修正した問題

これは外部モデルの提案ではなく、固定したbrowser-useのソースとアダプターを照合した発見。

1. `ChatGoogle(max_retries=0)` は固定版のassertで失敗する。総試行1回を意味する `1` に直し、Google SDKにもHTTP `attempts=1` を指定した。
2. Agent既定のjudge、失敗後の最終応答、履歴要約を無効化。失敗許容を1回、fallbackなしに固定した。
3. 1ステップ1モデル要求、全体最大5要求の送信前制限を追加し、空応答への暗黙の再要求や補助要求も上限を越えて送らない。
4. 入力/クリックを除くだけでは任意JavaScriptや他の操作が残っていた。閲覧ツールの許可リストを作り、未知のツール・JavaScript・ファイル操作・追加LLM抽出も除外した。
5. Agent初期化が失敗してもブラウザを閉じる。`done(success=false)` を成功とせず、`finished` と `completed` を分けた。

`workstation/research.py` と `test_research.py`、このフォルダのASSESSMENT.mdを確認してほしい。一般的なWebページ自身の通信まで完全に無害だと保証する仕組みではない。本人のログイン済みブラウザや既存プロファイルは指定していない。

## 意見を求める項目と回答形式

公開コードを根拠に、重大な順に最大5点を回答してほしい。根拠を確認できない点は「未確認」と書き、読んでいないコードを読んだことにしない。

各項目は「問題/提案」「根拠のファイル・関数・確認SHA」「どのアプリで採用すべきか」「16GB PCの負荷・依存・API要求数への影響」「最小の修正」「必要な確認」「採用/条件付き/保留」を示す。推論の逐語的な開示は不要で、判断根拠を簡潔に示す。

特に、独立環境の維持、Windows移行で失われるパス/DB/時刻、素材パックとDeliveryの対応、browser-useの暗黙の追加要求、CapCut形式の実機差、AGPLサービスとの境界について意見がほしい。追加の文字起こし・要約・監査・サービス常駐・別プロバイダーへの自動切替を勧める場合は、上の利用者条件と矛盾するため既定採用しない。
